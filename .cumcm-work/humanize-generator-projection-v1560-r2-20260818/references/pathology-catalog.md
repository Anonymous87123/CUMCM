# 纯文风病灶目录

本文件只判断文本如何说，不判断所说内容是否正确。诊断时先观察跨段重复、篇幅分配和收尾习惯，再看单个词。单个“因此”不是问题；连续段落用相同路标和闭合动作，才构成模板病灶。

## 使用方法

每个病灶包含“识别信号、规则、案例和改写”。案例是结构范式，不要求逐字套用。改写时优先处理病灶形成的跨句关系，不做同义词替换竞赛。

## HUM-01 固定机械句首复用

**识别信号**

- 连续段落以“本文”“本节”“首先”“进一步”“需要指出的是”起句。
- 同级小节都以“问题 X 关注的是”“对于 X 而言”“从 X 角度看”开门。
- 多个分析段都以“依据/基于某理论”“根据某框架”起笔，只替换理论名称。
- 多段重复“面临的核心问题是”“核心挑战在于”“关键问题是如何”等问题报幕壳。
- 句首像字段名，换一节只替换名词槽位。

**规则**

`HUM-01 MUST`：三个相邻自然段不得靠同一语法槽位启动。根据段落的真实重心，分别从对象、矛盾、观察、选择、结果或限定起笔；若上下文已明确对象，可直接进入动作，不补路标。

理论或问题句壳单次出现不构成病灶。只有跨段重复且理论名称、问题标签只是可替换槽位时才处理；不得按固定比例限制理论段首，也不得把具体技术问题强改成反问。

**案例**

机器写法：

> 问题一关注资源恢复。问题二关注珍稀物种恢复。问题三关注食物链的长期变化。

拟人改写：

> 资源恢复先说。珍稀物种的恢复另起一段；食物链的长期变化放在最后。

**改写动作**

1. 圈出相邻五段的前十二个字。
2. 删除只负责报幕的句首。
3. 用每段最独特的信息占据首句。
4. 保留必要复现的术语，不机械轮换同义词。

**不要这样修**：把“本文”依次换成“本研究、该工作、此项分析”。词变了，槽位没变。

## HUM-02 万能过渡词堆叠

**识别信号**

- “因此、由此可见、值得注意的是、进一步而言、与此同时”密集出现。
- 过渡词删掉后，句意和前后关系没有变化。
- 每段结尾先总结一次，下一段开头再过渡一次。

**规则**

`HUM-02 MUST`：连接词只在关系无法由内容顺序自行显现时使用。因果、转折、递进和并列必须各自有具体语言根据；相邻两句已自然承接时，直接连接。

**案例**

机器写法：

> 值得注意的是，两个区间的曲线形态并不相同。进一步而言，这种差异说明参数的影响具有阶段性。因此，有必要分别讨论两个区间。

拟人改写：

> 两个区间的曲线形态不同，参数作用也随之分成两个阶段。下面分开讨论。

**改写动作**

- 先删过渡词，朗读前后两句。
- 若关系仍清楚，不补替代词。
- 若关系不清楚，用具体关系替代空路标，如“前一段比较末值，这里改看变化速度”。

**不要这样修**：把“因此”换成“故而”，把“值得注意的是”换成“不可忽视的是”。

## HUM-03 虚假逻辑转折、无必要衔接与强行串联

**识别信号**

- “虽然……但是……”两侧并不冲突。
- “不仅……而且……”只是把两个普通事实绑成对称句。
- 为了保持章节流动，每段都添加“这为下一节奠定基础”。
- 内容本可并列，却被强写成单线因果链。

**规则**

`HUM-03 MUST`：只保留能够改变读者预期的转折。并列内容直接并列，弱相关内容允许分段，章节之间不必伪造因果桥梁。

**案例**

机器写法：

> 虽然该方法结构简单，但是它可以用于后续计算。不仅如此，它还为下一部分的讨论奠定了坚实基础。

拟人改写：

> 该方法结构简单，可用于后续计算。

**改写动作**

1. 写出连接词声称的关系。
2. 若两侧没有真正冲突、递进或因果，删掉框架。
3. 用对象复现、变量回指或动作变化形成自然承接。

**不要这样修**：为了“更顺”给每段加一句承上启下。人类文本允许话题在标题处自然切换。

## HUM-04 固定“观点—支撑—边界—过渡”流水线

**识别信号**

- 每段都先宣告观点，再补两句说明，再写一句限制，最后引向下文。
- 不同重要性的内容拥有相同四步结构。
- 限定句像模板义务，不改变段落实际读法。

**规则**

`HUM-04 MUST`：段落结构由本段任务决定。定义段可以一句结束；关键判断段可以展开；结果段可以停在现象上；限制只在本段确有解释作用时出现；过渡只在读者需要方向提示时出现。

**案例**

机器写法：

> 本节分析参数变化。结果显示曲线先升后降。需要说明的是，该结果仅适用于当前设定。上述分析为下一节的机制讨论奠定基础。

拟人改写：

> 在当前设定下，曲线先升后降。下一节讨论这一转折。

或在无需过渡时：

> 曲线在中间区间达到峰值，参数继续增大后反而回落。

**改写动作**

- 为每段只写一个功能标签：定义、比较、解释、判断、例子、回指或停顿。
- 删除为了凑齐四格而出现的句子。
- 连续三段不得共享同一功能序列。

## HUM-05 段落长度高度均匀、句子长度过度平衡

**识别信号**

- 相邻五段的行数和句数近似相等。
- 每段固定三至四句，每句都在相似字数处停顿。
- 短信息被拉长，关键内容被压成同样尺寸。

**规则**

`HUM-05 MUST`：原文、文档职责或 Voice Profile 已显示信息地位不等时，让篇幅跟随该差异。允许一句段、两句段和长段共存；正式等权条件、定义组和标准条款保持平行。不得为了制造变化随机拆句或凭空指定重点。

**案例**

机器写法：三个并列小节各四句，依次介绍定义、作用、优势和小结。

拟人改写：原文未显示三个概念的主次，因此保持平行，只删除每节重复的“作用—优势—小结”槽位。只有原文或 Voice Profile 明确显示分量差异时，才调整篇幅。

**改写动作**

1. 按段标记 A/B/C 重要度。
2. 检查 A 段是否真的比 C 段获得更多解释空间。
3. 合并被拉长的低信息句，释放短段。
4. 把关键判断单独落句，但不要把所有结论都做成口号。

## HUM-06 全文节奏极度规整，缺少疏密与留白

**识别信号**

- 每节都以背景铺垫开始，以总结展望结束。
- 公式、解释、例子和提醒按固定周期循环。
- 读者无法从节奏感知哪里是重点。
- 同一段反复使用破折号承担解释、转折和强调，停顿不再跟随对象变化。

**规则**

`HUM-06 MUST`：在章节尺度设计“铺垫—加密—停顿”而非重复节拍。背景只在首次需要时出现；关键处允许连续推演；例行处允许压缩回指；一个具体判断后可以直接换节。

破折号、冒号和分号由语义关系与 Voice Profile 决定，不设机械配额。单个破折号、标题副标题和引语中的标点保持不动；只有同段集中复用并形成固定节拍时才分句或改回普通停顿。

**案例**

机器写法：每个公式后均有“其中……这表明……值得注意的是……”三句解释。

拟人改写：第一个公式完整交代符号；第二个公式只说明新增项；决定性公式前放慢解释，之后用一句指出变化，不再逐项复述。

**改写动作**

- 画出一页内的密度曲线：背景、公式、解释、判断、例子。
- 若曲线近乎平直，重分详略。
- 保留真正需要读者停下来的位置，压缩其余旁白。

## HUM-07 公文腔、汇报腔、审计腔、说教腔、辅导员腔和模板学术腔

**识别信号**

- 正文出现“抓手、闭环、落地、赋能、统筹推进、全面提升”。
- 用“必须指出、需要强调、读者应当注意”持续指挥读者。
- 用“完成、通过、放行、风险项、状态”汇报写作过程。
- 学术腔依靠“具有重要意义、提供有力支撑”而非具体表达。

**规则**

`HUM-07 MUST`：把管理动作改回研究对象、学习对象或工程动作。删除对读者的纪律性指令；把写作过程状态移出正文；评价词只有在句中承担具体区分时保留。

**案例**

机器写法：

> 本节围绕核心目标形成分析闭环，为后续方案落地提供有力支撑。需要强调的是，读者必须准确把握这一关键机制。

拟人改写：

> 本节分析该目标及其作用机制，结果供后续方案使用。

**改写动作**

- 圈出管理、验收、宣传和训导词。
- 问“句子实际说了哪个对象的什么变化”。
- 能回答就改成对象句；不能回答就删除。

## HUM-08 空泛学术套话和抽象名词堆砌

**识别信号**

- “系统性、科学性、有效性、协同性、复杂性”连用，却没有具体承载对象。
- “实现了对……的深入探讨”“具有一定的理论和实践意义”可复制到任何主题。
- “综合运用、系统梳理、提供理论支撑、有效解决、完善理论体系、不可或缺”成束出现，却不说明方法分工或结果。
- 多段重复“该处理体现了、该设计基于、该决策反映了”，处理名词自动推出抽象价值。
- 同段连续用“作为重要载体、扮演角色、发挥作用”绕开直接判断。
- 动词名词化，句子只剩“开展、实现、促进、提升”。

**规则**

`HUM-08 MUST`：将抽象评价还原成可读动作、差异或选择。若一个短语不能回答“具体多了什么、少了什么、换了什么、保留了什么”，删除或改写。

以上词项都只是上下文候选。单次“作为”、明确的变量角色、标准依据和具体方法分工可以 `KEEP`。改写“该设计体现了”时只能使用输入已有的原因和后果；不得像旧范例那样补造研究者曾经犹豫、失败或调整方案的过程。

**案例**

机器写法：

> 该框架把资源、捕食和外部扰动放进同一组状态方程，三类影响可以在一条时间轴上比较；这种组织方式兼顾了多维因素。

拟人改写：

> 该框架把资源、捕食和外部扰动放进同一组状态方程，三类影响可以在一条时间轴上比较。

**改写动作**

1. 标出以“性、化、度、机制、体系、框架”结尾的词。
2. 区分必要术语与空泛评价。
3. 用对象和动作改写，不强求每句都“学术”。

## HUM-09 创新性表演、空洞拔高和虚假升华

**识别信号**

- “首次、系统、统一、全新、突破、范式”密集承担气势。
- 普通组织选择被写成“创新框架”。
- 段末突然上升到治理、社会价值或方法论意义。
- 用“顺应时代—破局关键—持之以恒践行”把普通对象包装成口号式价值链。

**规则**

`HUM-09 MUST`：纯文风改写删除表演性强调，保留原文已有的具体差异表达。不要在本 Skill 中判断差异是否真实；只把“宏大评价先行”改成“具体动作先行”。

**案例**

机器写法：

> 本文首次将原先分开的三个子模型接到同一时间尺度上，并用共享状态量传递上游变化，由此构建系统、统一且具有突破性的分析范式。

拟人改写：

> 本文把原先分开的三个子模型接到同一时间尺度上，并用共享状态量传递上游变化。

**改写动作**

- 删除“首次/突破/范式”后检查句子是否还有内容。
- 把剩余内容前置；若没有剩余内容，整句删除。
- 不擅自补写“更准确的创新性判断”，因为那属于另一层任务。

## HUM-10 教科书式逐行公式解释与无效赘述

**识别信号**

- 公式后逐项把符号读成中文，重复符号表。
- 每次代入、移项、化简都配一条旁白。
- 图表中肉眼可见的升降被逐句复述。
- 关键选择和例行计算获得相同解释密度。

**规则**

`HUM-10 MUST`：解释非显然选择、变量角色变化和决定性转折；压缩重复运算、符号朗读和可见趋势。课堂场景可多保留一步，建模与科研场景应更快回到对象和结果。

**案例**

机器写法：

> 将式（3）代入式（4），可以得到式（5）。然后对式（5）进行整理，可以得到式（6）。进一步化简式（6），最终得到式（7）。

拟人改写：

> 将式（3）代入式（4）并整理，得到式（7）。

**改写动作**

- 标记每条解释是“选择说明”还是“操作播报”。
- 保留前者，合并后者。
- 若关键选择藏在三步操作中，把选择单独说清，其余计算回指公式。

## HUM-11 结尾强制总结、升华和展望

**识别信号**

- 每节都出现“综上所述，本节……”。
- 结论重复摘要、结果和讨论，没有新重心。
- 普通段落末尾强行写“具有重要意义”“为未来奠定基础”。
- 删掉“奠定基础”后，改用“为理解/认识……提供线索”回填同一抽象收益。
- 用“不是简单的 A，而是更深层的机制问题”制造推进感，但 B 没有命名任何机制。
- 无实际后续内容也列“未来可进一步研究”。
- 先用“局限需要写清”安排写作，再用“后续如要完善”安排下一轮，而没有直接说明当前限制和未决动作。
- 多个案例段都以“此案例印证/揭示/挑战了”“从中可以看出”“这提示我们”点题。

**规则**

`HUM-11 MUST`：结尾只承担一种必要功能：落下判断、回收主线、指出尚未展开的问题或直接结束。没有新功能时删除结尾句。不得为了完整感自动生成总结、升华或展望。

“局限需要写清”是编辑后台，不是局限本身；删除该提示后，要么直接给出原文已有的范围/条件限制，要么保留
`UNRESOLVED`。同样，“后续如要完善”不等于具体研究计划；只有原文已给出待补对象、动作和原因时才能保留，
不得把一般性的补强愿望写成自动展望。

案例点题尾句只有在重复复述前文时才处理。案例本身是正式研究对象、尾句引入新的具体差异或裁判要点时保留；不得把旧壳轮换成“问题的关键在于”“既然如此”等新的统一尾句。

删除空结尾后重新检查新尾句。不得把“为后续研究奠定基础”迁移成“为理解该现象提供线索/启发/依据”，也不得把“深刻揭示机制”降级成仍未命名对象的“涉及更深层机制”。输入已有具体候选机制时，直接写候选对象及其限制；输入没有这些对象时，停在已有观察、范围限制或原始记录，不补造一个抽象收益出口。

**案例**

机器写法：

> 综上所述，本节通过上述分析全面揭示了该参数的重要作用，为后续研究奠定了坚实基础。

拟人改写：

> 删除该空壳句；若前文已有具体判断，让该判断直接收尾。

或直接删去整句，让图表后的具体判断成为结束。

**改写动作**

- 比较最后一句与本段前文；若只是复述，删除，并检查是否换壳回填了同一收益评价。
- 比较“展望”与正文；若没有具体未决动作，删除。
- 一个章节最多保留一个真正必要的回收段。

## HUM-12 无瑕疵、无侧重、无停顿的机器完美感

**识别信号**

- 所有问题都有完整答案，所有段落都有边界和收口。
- 作者从不跳过次要环节，也不暴露选择。
- 每个观点都被包装得同样圆满，文本没有局部粗细差。

**规则**

`HUM-12 MUST`：只通过原文或 Voice Profile 可确认的真实取舍打破完美感，而不是制造错误或作者立场。可省略重复解释并让具体判断自然停笔；“这里只看、其余沿用、不再展开”只是候选写法，重复使用时按 `HUM-16` 处理。

**案例**

机器写法：五个问题都用四段完成背景、方法、优点、限制和承接。

拟人改写：第一个问题因定义模型而详细；第二个问题只解释新增约束；第三、四个问题合并讨论共同参数；第五个问题直接围绕情景差异展开。结构差异来自问题职责，不来自随机打散。

**改写动作**

1. 写下作者真正最关心的一到两个位置。
2. 让这些位置获得解释峰值。
3. 合并重复的完整性部件。
4. 保留有限留白，不替读者完成所有归纳。

## HUM-13 句式对称过度与逻辑排布标准化

**识别信号**

- 高频使用“一方面……另一方面……”“既……又……”“不仅……还……”。
- 并列项句长、词性和评价完全镜像。
- “首先/其次/再次”“第一/第二/第三”或三个“从某维度看”机械复用，条目只为凑足三项。
- 优点、局限、建议总是等量出现。

**规则**

`HUM-13 MUST`：只有内容真正对举时才使用对称句。原文明确不等重时，重项可展开、轻项可并入从句；等权定义、条件、因素和标准条款使用 `KEEP`。并列数目由内容决定，不得为了 Humanize 人为破坏平行。

算法、证明、实验流程和规范步骤中的真实顺序不因命中枚举壳而改写。扫描器只给 `REVIEW` 候选；不得使用“每段最多一个三元结构”之类硬阈值。

**案例**

机器写法：

> 实验中最明显的变化是计算量下降；该方法同时提高了可解释性和适用性。

拟人改写：

> 计算量下降最明显；可解释性和适用性也有提高。

**改写动作**

- 拆掉成对连接词，比较两侧信息重量。
- 让最重要项占主句，次要项降为补充。
- 避免为了“三点完整”把一个意思拆成三条。

## HUM-14 统一化行文权重与每段均等用力

**识别信号**

- 背景、方法、结果、限制都使用相同篇幅和强调程度。
- 每个子问题都写同样多的“优点”和“局限”。
- 文本看起来全面，却很难复述作者究竟重视什么。
- 正文连续加粗多个“核心、关键、显著、重要”词组，用格式替代句位、篇幅和具体差异。

**规则**

`HUM-14 MUST`：从原文结构、用户目标或 Voice Profile 提取重心层级并让语言权重可见；不得由改写者自行指定 A/B/C。无法确认主次时使用 `REVIEW/NO_CHANGE`，不能让“反均匀”本身替代作者判断。

单次加粗、术语首次定义、表格字段和稳定列表标签可以保留。只有正文密集加粗且格式强调没有对应信息主次时才减少；不设全文五处或五十处等数量上限。

**案例**

机器写法：四个结果各写一段，结构都是“数值—解释—优点—限制”；原始结果中只有第二项出现反转。

拟人改写：先用一段比较四个结果，只把出现反转的第二项单独展开；其余三项在一句中交代共同趋势。读者一眼能看出真正改变判断的位置。

**改写动作**

1. 为章节列出一个主重心和不超过两个次重心。
2. 检查标题、篇幅、句长和例子是否体现该排序。
3. 合并等权重复段。
4. 删除“全面覆盖”造成的低价值解释。

## HUM-15 模态缓和堆叠

**识别信号**

- 一句内叠加“或许可以说、在某种程度上、一定的、可能、某些、相对而言”。
- 多个弱化词没有分别限定不同对象，只共同制造谨慎外观。
- 删除一个缓和词会改变强度，但无法判断应保留哪一个。

**规则**

`HUM-15 MUST`：区分真实认识强度与重复缓和。保留承担独立范围、概率或证据状态的模态；只有多个词限定同一命题且明显重复时才合并。无法确认强度时使用 `REVIEW/UNRESOLVED`，不得把“可能相关”改成“相关”。

**案例**

机器写法：

> 这一现象或许可能呈现初步规律，并可为后续分析提供某些线索。

拟人改写（仅在原意允许时）：

> 这一现象可能呈现初步规律，可作为后续分析的线索。

若“或许、可能、初步”分别承担明确强度，保持原文并标 `REVIEW`。

**改写动作**

1. 标出每个模态词限定的命题范围。
2. 合并只对同一命题重复降格的词。
3. 保留否定、条件、概率和未完成状态。
4. 用不变量检查器比较改前改后的模态标记。

## HUM-16 修复语模板化

**识别信号**

- 改写后多段以“这里真正、这里只看、只需、直接、其余沿用、不再展开”开头。
- 所有段落都被改成“对象先行 + 短判断 + 不总结”的同一新模板。
- 原作者惯用句法消失，场景默认声线取而代之。

**规则**

`HUM-16 MUST`：把修复语视为与原 AI 句壳相同的复用风险。相邻三段出现同一归一化修复骨架时重新改写或恢复自然原句。没有 Voice Profile 时采取最小改动，不用场景默认声线冒充作者个性。

**案例**

失败修复：

> 这里真正要看的是 A。这里只讨论 B。其余情形沿用前式，不再展开。

二次修复：

> A 决定本节的比较顺序。B 只在第二组出现；其他情形仍用前式。

**改写动作**

1. 对改后段首 4-8 字和句法槽位再次扫描。
2. 将修复短语纳入词库的重复窗口，而不是禁用一次出现。
3. 优先恢复作者原有自然承接方式。
4. 同版本复跑仍持续改写时标记非幂等。

## HUM-17 题目槽位和固定推演链泄露

**识别信号**

- 同一可编辑正文跨行反复出现“适用题目”“逻辑链条”“给定首句”或“此类题目可用”。
- 文字先列题型范围，再指令读者把任意开头填入预设的判断、号召、对照或升华链。
- 这些短语来自备课卡、作文模板或编辑备注，却以普通正文段落出现，读者无法知道它究竟是在解释对象还是在分发写作指令。

**规则**

`HUM-17 MUST`：只把跨行重复的组合标为候选，不能因一句“逻辑链条”就认定模板化。先判断文档身份：用户明确要求保留的教师备课单、题库说明或模板原件可 `KEEP`；面向读者的课程讲义可改成具体的题型条件和判断动作；论文、报告和普通正文不得保留“填入首句后套链条”式后台说明。不能把槽位说明直接改写成一个新的万能收尾；信息不足时回退为 `PATCH/ANNOTATED` 或 `UNRESOLVED`。

代码、公式、引语、题干和用户锁定的模板不进入该病灶的可编辑面。扫描器只提供 `REVIEW`，不授权删除任何内容；
`适用题目`、`逻辑链条`、`给定首句` 分别不足以证明作者身份或文本质量。

**案例**

模板化写法：

> 适用题目：若干主题。给定首句后沿固定逻辑链条写到结尾。

可编辑正文中的处理方向：

> 先说明本题比较的两个条件，再给出它们改变判断的原因。

后一句只有在原材料已给出比较对象、条件和原因时才可写入；否则只标出缺失槽位，不补造内容。

**改写动作**

1. 将题型范围、示例首句、固定链条和实际作者正文拆开登记。
2. 对仍可编辑的正文，只保留原文已经给出的对象、条件、动作和后果。
3. 用户要的是题库或教师备注时保留其功能，但在交付摘要中标记为模板/说明，不称为自然学术正文。
4. 改后重新扫描，确认没有把“适用题目”换成“本段适合”或把固定链条换成同功能的自动结尾。

## HUM-18 自我优点式对照跨段复用

**识别信号**

- 多个分析段都以作品自身的优点、价值、意义、贡献或关键为主语，随后用“不在于……而在于……”宣布该段正确性。
- 每次对照后都接不同数据、机制或限制，但段首的验收式话术不承担新增信息。
- 单次方法比较本来有明确取舍，却因连续使用同一自证骨架而读成批量“本方案值得采用”的背书。

**规则**

`HUM-18 MUST`：仅当该骨架跨至少两个不同段落重复时列为 `REVIEW`。保留对照本身所携带的对象、条件、数据、
范围和限制；只在材料足以支撑时把段首改成直接说明该段实际做了什么或哪个差异改变判断。一次真实的“价值不在于 A，
而在于 B”不得因形式相似被删除。没有可替代的具体对象时原样保留并标 `UNRESOLVED`，不能把它换成“这一点很重要”
或“由此体现优势”等另一种空泛自证。

该病灶不评价方法是否真的更好，也不证明文章由模型生成。它只限制同一文件把“作品自我评价 + 否定对照”批量当作
段落起句。题干、引语、代码、公式和用户锁定的评价句仍在保护区，扫描器不拥有裁决权。

**案例**

重复写法：

> 本研究的价值不在于增加术语，而在于显示条件差异。

下一段再次以同一“价值不在于”结构开头，即使后文讨论的是另一组数据，也应先审计段首是否只是固定背书。

可编辑方向：

> 两种条件在该比较中分别改变了不同结果。

这不是通用替换句；只有原材料明确给出两种条件、比较对象和结果时才可采用。

**改写动作**

1. 把每个自证段首与其后真正新增的数据、条件、机制或限制分开标注。
2. 留下一处有必要的比较，其他段落直接从本段差异进入。
3. 改后检查没有连续换成“真正的价值”“核心优势”“关键意义”等同功能词。
4. 若用户锁定评价主张，保留原句并降级为 `PATCH/ANNOTATED`，不输出假装完整的 `CLEAN`。

## HUM-19 跨小节优点-局限-补强验收块

**识别信号**

- 两个或更多同级小节反复按固定顺序安排：先用“本问/本模型的优点不在于……而在于……”为本节自我背书，随后用“其局限需要写清/说明/交代”提示写作动作，最后以“后续若继续补强，应优先……”列出补强事项。
- 每节的参数、数据或限制不同，但三种功能被同一组验收式话术绑定，读者连续读到的不是各小节真正不同的论证压力，而是五次相同的“优点、局限、改进”回路。
- 单个优点对照、一个真正的限制段或一次具体的后续研究都不构成这一病灶；缺少其中一环，或三环不在同一小节中，也不触发组合候选。

**规则**

`HUM-19 MUST`：只在至少两个同级小节完整复用该顺序时给出 `REVIEW`。先拆开每一节内真正的对象、证据、限制和未解决问题；不得把“有局限”或“未来可研究”本身当作应删除的内容。若材料足以支撑，可把非首节的自评壳改成该节首先改变的条件、结果或范围，把编辑性“需要写清”改为直接陈述限制；没有能够承接的具体信息时，保留原文并标 `UNRESOLVED`。

扫描器只报告每个完整小节中首个自评壳，且会拒绝从代码、公式、引语或其他保护区借用任一组成部分来凑成三元组。它不评价模型是否有优点、不判断限制是否成立，也不据此判断作者身份。规则输出不得自动删除、不得要求删去真实局限或未来研究，也不得把所有结尾替换成同一个“仍待进一步验证”。

**案例**

重复写法：

> 本问的优点不在于增加参数，而在于分开两类条件。\n
> 其局限同样需要写清：当前结果只适用于固定样本。后续若继续补强，应优先加入独立样本。

下一小节以同样三个角色重复，即使其中换成了另一组参数，也应检查该小节是否真的需要先做自我验收、再声明“需要写清”、最后写出补强计划。

**改写动作**

1. 对每个命中小节分别列出自评壳、事实限制和补强动作，不能把一节的事实移给另一节。
2. 至多保留有必要的一处方法比较；其余小节从本节实际条件、结果或限制直接进入。
3. 删除编辑提示时只删“需要写清/说明/交代”这一壳，限制本身必须保持原有模态、范围和证据状态。
4. 改后重扫 `HUM-18`、`HUM-19` 和未来展望信号，确认没有改成“真正的优点”“需要注意的局限”“下一步仍应补充”等同功能轮换。

## HUM-20 问题分析开头的否定纠偏模板

**识别信号**

- 三个或更多“问题 X 分析”同级小节都在前部用“问题 X/本问/这一问 + 不是……而是……”来宣布任务。
- 每节真正讨论的变量、约束或模型不同，但开场先预设一个被否定的低层任务，再把本节抬升为“真正要回答”的任务；连续阅读时，差异被同一纠偏动作遮住。
- 单次“不是 A 而是 B”、课程题解中用于纠正误读的对照、普通讨论标题下的真实比较均不构成该病灶。

**规则**

`HUM-20 MUST`：只在至少三个明确的“问题 X 分析”小节、且每次都在开头 1600 字内由问题主语引出同类否定对照时标为 `REVIEW`。先判断每一节是否确实需要纠正一个可见误读；如果 B 可以独立陈述，优先从该节具体对象、条件或判断直接进入。不得删除实际互斥条件、真实教学纠偏或题目要求，不得把所有开头换成“本问重点是”，也不得据此判断作者身份。

公式、代码、引语、题干和用户锁定句不能提供匹配组成部分。扫描器只定位每个合格小节的对照壳；它不裁决 A 或 B 的内容正确性，也不自动改写任何数值、对象、范围或结论。

**案例**

重复写法：

> 问题一不是比较单点末值，而是区分两个阶段。\n
> 本问的重点不是比较哪个对象更大，而是说明约束怎样改变结果。\n
> 这一问真正要回答的不是某时刻数值，而是系统属于哪类状态。

只有这些句分别位于至少三个“问题 X 分析”小节前部时，才审计它们是否是同一任务说明模板。若原文没有足够对象支撑直接起笔，保留句子并标 `UNRESOLVED`，不要补造更具体的研究问题。

**改写动作**

1. 逐节列出被纠正的实际误读和本节已有的对象、条件、判断；没有误读的 A 只算句壳，不计作内容。
2. 保留最多一个真正需要的纠偏；其余小节从本节变量、比较条件或待区分状态直接进入。
3. 改后检查没有批量换成“本问重点是”“真正需要说明的是”或“核心在于”等同功能的统一开场。
4. 与课程内容混合时，先按场景保留有明确学习动作的纠偏句；本规则只在 `MODELING` 场景生效。

## HUM-21 问题模型开头的误读预演清单

**识别信号**

- 三个或更多“问题 X 的模型建立与求解”同级小节，在前部反复用“为避免把/将……混为一谈”“为避免只凭……判读”或“为了避免……误写成……”预演一个错误读法，再进入模型对象。
- 每次的对象和限定可能不同，但句首都先替读者排除一个误读；连续阅读时，章节开头像统一的检查清单，而不是从当前变量、事实或方程直接进入。
- 单次的口径区分、图像判读限制、阈值稳健性说明和保护性假设不构成该病灶。

**规则**

`HUM-21 MUST`：只有至少三个明确问题模型小节、且匹配均位于小节开头 1600 字内时，才列为 `REVIEW`。先检查被避免的误读是否真实存在以及后句是否已经给出对象；若限制本身提供了必要条件，保留它。扫描器只定位每个合格小节的首个句壳，不自动删除“为避免”，不改写对象、数值、证据或模型边界，也不以该模式判断作者身份。

**案例**

病灶例：

> 问题一的模型建立与求解：为避免把候选集合与约束集合混为一谈，本节先分别定义两类符号。
>
> 问题二的模型建立与求解：为避免只凭输出次序判读，本节先写明比较条件。
>
> 问题三的模型建立与求解：为了避免将参数调整误写成状态更新，本节先固定评价对象。

正常反例：

> 问题一的模型建立与求解：为避免把边界条件并入初始条件，本节分别列出两组约束后再建立关系式。

病灶例只有在三句分别位于三个同级模型小节前部时才成立：三个开头都先预演误读，再进入本节对象。正常反例只出现一次，而且该区分直接限定后续关系式，应保持 `KEEP`。若三节候选中某一处确实承担必要限定，只对该处记 `KEEP`；不能因它加入命中簇就自动删除。

**改写动作**

1. 逐节登记被区分的口径、变量或判断，以及句壳之后真正新增的模型动作。
2. 至多保留一次确有必要的误读纠偏；其他小节从已有对象、事实或方程直接起笔，避免把“为避免”换成“需要指出的是”等新路标。
3. 若没有足够材料支撑直接起笔，保留原句并标 `UNRESOLVED`，不能为了消除候选补写误读或结论。

## HUM-22 问题分析的收益自证回路

**识别信号**

- 三个或更多“问题 X 分析”同级小节反复出现“这样的分析既能……”“这样写……就会更完整”“这样处理的好处是……”或“这样……才能从……上升为……”等句壳。
- 句壳评价的是证据链完整、任务完成、结论升级或写作收益，后文可能仍有真实数据、机制和限制；病灶在于同一验收式说明跨小节复用，不在于收益关系本身必然错误。
- 一次说明设计造成的直接变化、一个由数据支撑的结果后果或一个必要的方法理由，不构成该病灶。

**规则**

`HUM-22 MUST`：仅在至少三个问题分析小节各自出现该类收益/完成度壳时列为 `REVIEW`。先分离句壳和其后的对象、数据、机制、限制或建议，再判断是否能从具体变化直接进入。不得把“才能”承载的真实因果改成无条件结论，不得把一次收益说明轮换成“更系统/更完整/更清晰”等同功能模板；候选不授权删除结果或判断。

**案例**

病灶例：

> 问题一分析：这样的分析既能补足说明，也能让论证更完整。
>
> 问题二分析：这样处理的好处是后文可以形成统一说明。
>
> 问题三分析：这样写，当前判断才能从结果罗列上升为整体解释。

正常反例：

> 问题一分析：采用同一标度处理后，两组输出可以在同一尺度下比较。

病灶例跨三个同级分析小节评价写法的完整度，具体对象退居验收壳之后。正常反例直接说明处理方式造成的条件性结果，不评价文章是否“更完整”，应保持 `KEEP`。`这样……才能` 也可能承载真实因果；即使它与另外两节共同进入候选簇，也必须逐处复核，不能按词形自动改写。

**改写动作**

1. 为每个小节标注句壳声称的收益，以及原文实际给出的支撑关系；缺少支撑时标出缺口，不补造事实。
2. 至多保留一处承担跨段解释职责的收益说明，其他小节优先直接写当前对象如何变化；保留模态、条件和证据状态。
3. 改后重扫“这样写/这样处理/这样……才能”及 `LEX-SELF-VALIDATION-01`，确认没有把旧验收腔替换为新的完成度口号。

## 组合病灶

真实文本通常不是单一病灶。优先按下列组合处理：

| 组合 | 表面症状 | 处理顺序 |
|---|---|---|
| `HUM-01 + HUM-02` | 起句和过渡都像批量生成 | 先删除报幕句首，再判断是否仍需连接词 |
| `HUM-04 + HUM-05 + HUM-14` | 每段四句、等长、等重 | 先重分段落职责，再分配篇幅，最后修句子 |
| `HUM-07 + HUM-08` | 管理词和抽象名词一起堆积 | 找回具体对象与动作，无法还原的信息直接删 |
| `HUM-09 + HUM-11` | 开头宣称创新，结尾强制升华 | 前后同时降载，让正文中的具体差异成为重心 |
| `HUM-10 + HUM-12` | 每一步都解释，文本无留白 | 确定解释峰值，例行步骤压缩回指 |
| `HUM-13 + HUM-14` | 并列完美、所有部分等权 | 打破假对称，主句只留最重要差异 |
| `HUM-15 + HUM-08` | 多重缓和包住空泛评价 | 先锁认识强度，再删除无信息评价 |
| `HUM-12 + HUM-16` | 用统一修复语制造“取舍感” | 回到 Voice Profile 与最小改动 |
| `HUM-17 + HUM-09 + HUM-11` | 题型槽位后自动拔高和收尾 | 先移出后台指令，再分别审计拔高与结尾，不用另一套模板替换 |
| `HUM-18 + HUM-13` | 多段用同一优点式否定对照开头 | 保留真实比较，打散验收式段首，不把它改成另一组自夸词 |
| `HUM-19 + HUM-18 + HUM-11` | 每节都按优点、局限、补强三段验收 | 先保留各节限制和未决问题，再拆掉重复自评壳与编辑提示；不要删成没有限制的“完成态” |
| `HUM-20 + HUM-02` | 各问题都先否定一个假任务再用相同过渡推进 | 先核对真实误读，再从该节对象进入；不要把任务说明换成另一组报幕句 |

## 诊断禁忌

- 不按关键词出现一次就判 AI 味。
- 不以句长方差、词频或段落长度单独判定作者身份。
- 不要求每段故意长短不同；变化必须有信息理由。
- 不把口语、俚语、第一人称或错别字当作“人类证据”。
- 不把内容层的问题偷换成文风病灶。
- “专家认为、研究表明、一些学者指出”等是归因来源言语行为。可以标记“当前句中来源不可见”供人工复核，但不得在纯文风层核验来源、删除归因后改成客观事实，或虚构作者、年份和引文。
