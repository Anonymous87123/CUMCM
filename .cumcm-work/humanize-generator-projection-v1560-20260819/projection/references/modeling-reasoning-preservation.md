# 建模正文的公开判断保真

## 1. 适用范围

本文件只在 `SCENE=MODELING`、数学建模论文或工程决策稿中读取。它保护原稿已经公开写出的
判断依据，不要求输出隐藏思维链，也不允许把缺失的试算、候选路线或失败经历补写进去。

## 2. 四类可见节点

改写前先在当前 source span 中定位实际存在的节点：

1. `observation_constraint`：题面事实、数据记录、现象、约束、边界或假设；
2. `mathematical_change`：变量、参数、目标、方程、状态、指标、边界或数据口径怎样变化；
3. `method_choice`：为何采用、排除或调整某个模型、算法、求解方式或参数化；
4. `result_limit`：得到的结果、比较、检验、适用范围、不确定性、失败条件或限制。

节点不存在时不补造；它在 source 中存在时，候选不得无理由删除。四类不是固定正文模板，
也不是要求每一问都按同一顺序写，而是用来防止把真实判断压成“直接采用某模型”。

## 3. 改写规则

- 保留原稿中“事实/约束怎样改变数学对象，数学变化为何影响方法选择，结果能说明到哪里”的
  可追溯关系；可以合并重复句，但不能把关系改成并列的模型介绍。
- 如果 source span 已先写观察、试算或约束，再出现模型名，candidate 不得把模型名提到前面，
  也不得把“计算后发现、只能、仍需、仅在”等原有判断删成无条件结论。
- 允许保留功能性短句和不完全对称的段落节奏。不要为了消除“因此、从而、但是”批量换词；
  连接词承担判断关系时应原样保留或用等价的具体关系承接。
- 只有在确认被删内容是重复读数、重复定义或重复章节导览时，才接受明显压缩；若丢失一个
  source 中已有节点或节点之间的关系，降为 `REVIEW/2`，回到源事实或公式做局部修订。
- 候选没有依据时不得用“具有指导意义、为后续提供支撑、从而得到”等空泛句补齐缺口；
  这类句子既不是判断节点，也不是人类思考过程。
