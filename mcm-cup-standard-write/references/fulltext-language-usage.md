# 59 篇全文语言记忆的实际用法

## 1. 这不是一组替换词

本资料把 2020--2025 年 A/B/C 题 59 篇编号论文的正文段落作为语言记忆。页级语料共 2892 页，经正文边界重建后得到 8293 个段落；7679 个段落可用于总体模式统计，其中 2871 个标为高质量。448 个关键正文页另以 220 DPI 复识，362 页通过置信度与正文覆盖双门后采用，86 页保留原文本；继续排除少于 30 个汉字的短片段、关键词、步骤块、未完整收束、异常拉丁串和已知 OCR 错词后，有 1632 个进入默认写作检索。详细数字以 `fulltext-style-stats.json` 为准，逐段文字以 `fulltext-style-index.jsonl` 为准。

真正需要迁移的不是某几个“人类惯用词”，而是四件事：

1. 作者在什么局部事实出现后才说出模型名；
2. 一段里哪些句子属于同一个动作，哪里自然换段；
3. 公式、图表、试算和后问怎样接回正文；
4. 作者在证据用完时怎样停下，不补一个空泛总结。

全文索引是记忆主体，本文件是调用说明。任何概括都不能代替检索原段及其相邻段。

为防止文风验证只在已经被规则看过的段落上成立，`query_style_patterns.py --source fulltext` 默认排除 `style-benchmark-holdout.json` 列出的封存记录。该排除不减少语料统计覆盖；它只保护保留集不进入日常写作提示。`--include-reserved-holdout` 仅用于执行相应的冻结盲测，不能作为日常检索开关。

套件定义、原段文字、论文页码、索引行号、开发/保留不重叠和工作区冻结快照由下列命令交叉审计：

```bash
python scripts/audit_cumcm_style_benchmark.py --runs-root .cumcm-work/aigc-style-benchmark --format text
```

从包含 `.cumcm-work/aigc-style-benchmark/` 的工作区根目录运行；若只核对语料来源、
保留集隔离和套件文本而不核对某次冻结运行，可显式加入 `--no-run-check`。

该命令不评价候选文风，也不检查数学正确性；它只确保盲测所称的“CUMCM 保留语料”没有被换段、改字或错误地重新放回常规检索。

## 2. 写一节正文前怎样调用

先确定当前节真正要完成的动作，而不是先确定要套哪种句式。常见动作包括：定义对象、把题意写成关系、说明近似授权了哪一步、推导方程、交代搜索、报告结果、解释异常、检验局部结论、说明适用边界。

随后检索 3--8 个同题型、同章节、同动作的完整段落，并保留前后各一段：

```bash
python scripts/query_style_patterns.py --source fulltext --problem-type A --section model --query 边界 --action derivation --limit 5
python scripts/query_style_patterns.py --source fulltext --problem-type B --section analysis --query 可行 --action choice --limit 5
python scripts/query_style_patterns.py --source fulltext --problem-type C --section result --query 残差 --action explanation --limit 5
```

若已经知道模型，可加 `--model`；需要回看单篇公开判断轨迹时，再用 `--source card`。检索结果只回答三个问题：本段从什么事实起笔，模型或结论在第几句出现，作者写到什么位置便停止。对象、数字、变量和结论必须来自当前题，不能从范文迁移。

不要同时模仿八个段落。选一个最接近当前动作的主段，另取一两个段落观察不同写法；其余只用于确认这种差异确实存在。

## 3. 模型不是总在同一位置出现

全文低噪声段落中可自动定位的模型首次出现共有 106 次，涉及 41 篇论文。它们不是同一条“困难--比较--选择”链。自动统计得到九类入口；另有人工论文卡确认的“现实后果转化为数学边界”，因相关段落未必出现词表中的模型名，不与 106 次自动命中混算。

### 前问结果承接

先点明沿用什么，再指出本问改变的输入、目标、约束或自由度。旧模型通常只需一句，不重新介绍原理；篇幅留给新增部分。A 类常见几何或状态递推沿用，B 类常见目标或约束替换，C 类常见预测输出接入评价或决策。

### 数据或图表观察引入

先写曲线、散点、残差、分布或分组差异中真正可见的现象，再说明这一现象要求怎样的函数形态、分段方式或误差结构。模型名可以到第二段才出现。不能把“数据呈现一定规律”当作观察，必须写清方向、拐点、平台、离散程度或异常区间。

### 解析或计算困难促成替代

先点名困难来自哪里，如边值条件复杂、变量域过大、状态数增长、全枚举超出预算，再说明采用离散、降阶、启发式搜索或分层求解。只写“问题复杂”不构成理由。被放弃的方法只有确实推导、试算或受规模排除时才出现。

### 现实后果转化为数学边界

先写继续放宽参数会造成的可观察后果，如构件倒退、资源断供、风险越界或操作不可执行，再把后果写成下界、上界、互斥条件或可行域。这里的重点是现实动作与数学条件之间的对应，不是“考虑实际情况”六个字。

### 约束结构导出模型

决策变量和业务规则已经足够明确时，目标函数与约束会自然导出规划、网络或状态模型。先把变量域、互斥关系、容量、先后次序或状态转移写清，模型名可以在结构形成后出现。

### 显式依据后选用

作者确实面对方法选择时，依据通常很局部：方程类型、变量是否整数、样本是否纵向、目标是否多目标、搜索空间大小、误差是否异方差。写到足以区分候选即可，不必列方法百科。

### 关系推导后自然落式

守恒、定长、几何相交、概率定义和成本恒等式可直接导出方程。此时关系来源、变量含义、多根筛选和边界比“为什么选这个模型”更重要。没有候选比较也是完整的建模判断。

### 由题意对象直接建模

题目已经给出明确目标、资源和规则时，作者会在重述局部对象后直接定义变量与目标。篇幅应花在口径和约束来源，而不是补一段空泛的选型故事。

### 局部陈述中直接出现

有些模型名出现在定义、公式说明或本节任务句中，前一段没有独立的选型叙述。这不等于作者没有思考，而是关系已由更早的题面、章节标题或前问建立。迁移时应回看更宽的章节上下文；若当前题也具备同样明确的关系，可以直接进入定义，不能强补一段比较。

### 首次模型之后的试算修正

先报告哪一段误差、哪个约束或哪个事件不符合要求，再只改动造成问题的局部结构，其余部分保持。修正后紧接同口径结果。没有真实试算和输出时不得使用这种写法。

这类修正多发生在模型首次出现之后，也可能直接触发第一次换模；当前自动首现统计中有 1 次落入此类。所有类型都是检索入口，不是正文小标题，也不是一问必须走完的步骤。

## 4. 人类公开判断为什么不显得机械

### 判断分散在工作发生的位置

获奖论文的公开判断并不全挤在“问题分析”。方程性质在离散方法前说明，候选根筛选紧跟求根式，搜索预算在算法切换前说明，异常原因跟在图表读数后，后问接口出现在下一问开头。这样读者看到的是工作推进，不是事后编排的选型表演。

### 同一问允许轻重不均

能由题意直接列出的关系写得短；首次出现的边界、失败试算、多根筛选和结果反转写得长。公式密集段可以只有一句引入和一句释义，图表改变结论时可以连续解释数句。不要为了“完整”把每一小节修成相同长度。

### 方法名可以延后

数据形态、物理边界或代数结构尚未说明时，不急着说模型。先让读者看到对象怎样变化，随后给出函数、约束或状态；模型名出现时应当像对已经形成的数学结构命名。

### 直接落式不是缺少思考

当定长、守恒、固定距离或成本定义唯一确定关系时，直接定义变量并列式是成熟判断。此处真正要公开的是坐标选择、量的方向、根的物理筛选和适用边界，不是虚构“比较多种模型”。

### 反例和事件切换比通用评价更有信息

终点可行但全过程失败、参数微变导致首次触发对象改变、局部残差方向相反、某一约束成为活跃约束，这些事实会自然带出修正或解释。它们比“模型具有较高准确性和鲁棒性”更接近实际工作。

## 5. A/B/C 题的段落重心

### A 类

A 类模型建立段的单篇正文字数占比中位数约 31%，求解约 16%，问题分析约 9%。模型段约 58% 的段落邻近公式，明显高于其他题型。正文常从坐标、几何关系、守恒、初边值条件或运动次序进入；一旦出现多根、首次事件、分段路径或离散误差，作者会在公式附近展开筛选理由。结果段优先解释局部轨迹、极值位置、误差随步长的变化和物理可行性。

写作时：

- 坐标系和正方向在首次推导前交代；
- 假设要说明它删掉了哪个维度或相互作用；
- 数学根之后写物理次序、方向和连续性筛选；
- 离散方法写网格、步长、边界处理和误差检查；
- 参数变化造成事件对象切换时，按事件解释跃变，不强行解释为连续趋势。

### B 类

B 类问题分析段的单篇字数占比中位数约 16%，高于 A、C；模型建立约 32%，求解约 11%。分析段中的选择、可行性和同口径比较较多。作者常先把业务规则拆成决策变量、成本项、互斥条件和状态转移，再决定规划、图论、动态规划或搜索方法。结果段不仅报最优值，还要回答方案是否可执行、资源是否断裂、哪项约束限制了进一步改进。

写作时：

- 每个决策变量对应可执行动作，不只给字母；
- 收益与成本统一时间、数量和结算口径；
- 硬约束、软偏好和目标函数分开；
- 枚举、剪枝、递推或启发式算法写清状态、更新和停止；
- 候选方案只在同一指标、同一约束下比较；
- 多人或随机信息改变时，先重写可见状态，再改决策接口。

### C 类

C 类模型建立段的单篇字数占比中位数约 38%，是三类中最高；问题分析约 11%，求解约 8%，结果约 9%。模型段除了公式，还承担字段语义、样本单位、清洗口径、代理变量、训练测试隔离和预测到决策的接口。结果段较常使用图表观察与机制解释，但因果结论必须受数据设计限制。

写作时：

- 先确定一行数据代表人、企业、日期还是一次测量；
- 缺失、异常、重复和合并规则写出对象及影响；
- 可视化只保留会改变分组、变换、模型或评价指标的现象；
- 模型选择由因变量类型、时间依赖、组内相关、非线性或类别不平衡引出；
- 训练、验证、测试及标准化拟合范围明确隔离；
- 系数、特征重要度和聚类标签只作其方法允许的解释；
- 预测值接入排序、分配或策略时，明确接口和阈值。

## 6. 各章节的语言组织

### 摘要

摘要按分问推进，但不机械复制同一句式。每问只保留对象、关键处理、模型或算法、主要数值结果和必要检验。能量、概率、收益等口径不同的结果不能只列数字。常见入口为“针对问题……”或“对于问题……”，但连续四段都这样起笔会暴露模板；可以从前问承接、条件变化或结果对象起笔。

摘要中的模型名可以直接出现，因为详细理由在正文承担。摘要不得补入正文没有的比较、检验和结论。

### 关键词

关键词是术语清单，不是正文语言样本。保留题目对象、核心模型和关键算法，避免把“数学建模”“数据分析”等泛词填满位置。

### 问题重述

只重写会进入模型的对象、任务、约束和输出，不复制故事背景，也不提前宣布解决方案。多个条件宜按对象或时间顺序组织，避免“首先、其次、再次、最后”成为唯一骨架。重述完成后应能回答每问输入什么、求什么、受什么限制。

### 问题分析

本节说明数学缺口，不写算法目录。自然段通常只承担一个局部变化：已有量与未知量、前问可复用部分、新增困难、数据现象、可行域变化或计算负担。模型名可以在段末，也可以留到模型建立处。若替换问题编号后各问分析仍可互换，说明没有写到题面对象。

### 模型假设

每条假设最好包含对象、忽略或近似内容、授权的数学处理。显然题设不必改写成假设，求解结果也不能倒写成假设。假设语气通常直接，用“忽略”“视为”“认为在……范围内不变”；有量级或图表依据时紧随其后。写完即停，不补“使模型更易求解”。

### 符号说明

表格负责集中列符号，正文只在首次推导附近解释容易混淆的量。符号按对象、时间、索引或状态成组，不要按字母顺序破坏关系。单位、取值域、下标含义和决策/参数属性比长篇文字更重要。

### 模型建立

模型段承担最多语言与公式接口。先写关系来源，再列式；式后只解释新量、非显然条件、多根或边界。连续公式之间可用“代入”“联立”“整理得”“由式……可得”，但这些词后面必须真有对应动作。定义、推导、约束和模型汇总可分段，不需要每段总结“至此模型建立完成”。

### 模型求解

求解段写实现中的状态变化，不搬算法教材。初始化写当前题的数据和状态，更新写哪些量被重新计算，停止写阈值、轮数、首次事件或误差条件，输出写回哪张表或下一问。若算法只是调用标准求解器，交代变量规模、整数性、非线性或求解器设置即可。

### 结果报告

先给正文裁决需要的结果，再放图表。文字不逐格朗读；只指出最优方案、关键区间、活跃约束、异常点和与前问不同的地方。“计算得到”“求解得到”“分别为”常用于落数，但不应连续重复。完整方案、坐标或逐期数据进入附录。

### 结果解释

解释从具体读数或图形特征开始，随后说明局部机制和对结论的影响。常见承接词有“由图”“图中”“说明”“导致”“这是因为”，但真正的人类感来自后面的对象与机制。趋势平稳时一句即可；反转、突增、事件切换或反直觉排序才值得展开。

### 模型检验

先说检验对象，再说方法和指标。回代、守恒、残差、交叉验证、基准比较、收敛和反例各有不同职责。检验只支持其直接结论：步长加密只能说明数值解在该网格附近稳定，分类指标只能说明测试集表现，不能自动推出普适性。

### 灵敏度与稳健性

写清扰动哪个参数、范围多大、其余量是否固定、输出如何变化、方案是否切换。若只做一次步长调整，就叫步长检查；若只改变一个参数，就不要写“模型整体稳健”。有阈值切换时分段解释，不用单一平均变化率掩盖。

### 模型评价

优点回到本题做成的具体结构，如保留物理边界、降低变量规模、统一结算口径或处理组内相关；不足回到已知的数据缺口、简化、误差源或计算预算。不要列“简单易懂、准确性高、适用范围广”三项套话。若没有证据支持推广，评价停在当前数据与条件。

### 改进

改进应与一个已识别不足一一对应：补哪类数据、放开哪个假设、替换哪个误差结构、增加哪层验证。只说“未来可引入更先进算法”没有接口，不写。改进不应暗示本轮已经实现。

### 参考文献与附录

参考文献只收实际使用的外部定义、算法或资料。附录要能从正文找到入口，代码文件、数据表、图形和输出名称相互一致。正文讲裁决逻辑，附录保留完整循环、参数表、日志和大结果；两者不是重复抄写。

## 7. 惯用词如何才有作用

跨篇较稳定的词语包括：

- 题意入口：“针对问题”“对于问题”“根据题意”“由题意”；
- 定义动作：“设”“记”“令”“若”“当”；
- 推导接口：“由此可得”“根据上述分析”“整理得”“化简得”；
- 选择动作：“采用”“选择”“选取”“综合考虑”；
- 前问接口：“进一步”“同理”“在问题一/二的基础上”；
- 求解动作：“初始化”“迭代”“更新”“遍历”“步长”“终止条件”；
- 图表接口：“由图”“图中”“由表”“表中”；
- 结果落点：“计算得到”“求解得到”“最终得到”“分别为”；
- 解释动作：“说明”“表明”“导致”“意味着”“这是因为”；
- 检验动作：“误差”“残差”“扰动”“交叉验证”；
- 边界动作：“在一定范围内”“适用于”“未考虑”“仍有”。

这些词不能按同义词轮换。先判断句子是否真的执行了对应动作；若没有，删掉词，而不是换一个。连续多段以“针对”“首先”“通过”“结果表明”开头时，应检查段落是否本来就在重复同一结构。

## 8. 段落边界与节奏

同一对象、同一公式链或同一次局部判断可以留在一段。对象改变、证据类型改变、从推导转入算法、从结果转入原因、从当前问转入下一问接口时通常换段。

以下情况允许短段：

- 一句给出定义，下一行紧接公式；
- 一句说明唯一边界或停止条件；
- 一句把前问输出接入后问；
- 一句指出表格中无需展开的显然读数。

以下情况应展开：

- 多根或多候选需要物理/业务裁决；
- 试算失败触发模型修改；
- 参数变化导致事件对象或最优方案切换；
- 图表出现反直觉趋势；
- 近似直接改变适用边界；
- 检验结果限制了结论强度。

段落在当前动作完成后停止。不要习惯性补“为后续研究提供基础”“说明模型具有有效性”“具有重要现实意义”。

## 9. 写后复核

逐问找到模型或算法第一次出现的位置，向前读两段：读者能否看到题面对象、数据现象、关系推导、约束结构、计算困难或真实试算中的至少一种依据？若不能，补的是具体依据，不是固定选型段。

再逐段回答：

1. 本段只做了什么主要动作？
2. 这一动作使用了哪条当前题证据？
3. 哪一句把它接到公式、图表、结果或下一问？
4. 最后一句是否在证据用完后仍继续拔高？

若四个问题只能用抽象词回答，应回到代码、图表、题面或全文检索结果，而不是继续润色。
