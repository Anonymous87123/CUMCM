# 25--30 页正式竞赛正文模式

## 目录

1. 计数口径
2. 长稿工作流

5. 扩写与压缩规则

## 1. 计数口径

本模式只在用户、学校或当届要求正文约 25--30 页时启用。页数不是普遍获奖条件，也不得冒充官方统一限制。

“正文页”从问题重述首页开始，到结论或模型评价末页结束。下列内容不计：

- 封面、承诺书、编号页；
- 摘要、关键词、目录；
- AI 工具使用说明；
- 参考文献；
- 附录、代码、全量数据表和支撑材料。

在 TeX 中把 `\label{mcm-body-start}` 放在问题重述首段前，把 `\label{mcm-body-end}` 放在结论或模型评价最后一段后。审计器读取编译生成的 `.aux`，按包含首尾页计数：`end_page-start_page+1`。

## 2. 长稿工作流

1. 先完成可复算的压缩稿，不在模型尚未跑通时规划 30 页措辞。
2. 建立逐问覆盖清单，找出真正缺少的数学和证据接口。
3. 按分问优先补模型建立、求解、结果和检验；再补必要的数据口径、假设依据、符号和跨问接口。落笔前运行 `prepare_style_retrieval_plan.py`，为每个可写章节绑定 3--8 个已核验全文段落及相邻上下文；再用 `prepare_section_authoring_brief.py` 把章节所属分问的本题事实、数学落点、实际路线和真人预审与这些语料 ID 对齐。语料只提供行文动作和收束方式，不提供当前题目的事实；底稿字段也不是正文段落顺序。
4. 每新增一节都要对应真实公式、代码、图表、试算、结果或边界。仅解释算法通用原理的段落不计作有效扩展。
5. 编译并运行页数审计。低于 25 页时，根据审计器给出的缺口继续补；超过 30 页时移动支撑材料，不通过缩小字号或压行距硬塞。
6. 页数通过后运行内容密度审计，核对每问实际页数、段落、公式、图表、结果解释，以及全稿各功能区的篇幅分布、重复正文和版式填充信号。
7. 发布前运行 `audit_style_retrieval_plan.py`，核对计划与最终选定稿件的哈希、章节目标、锚点数量和盲测保留排除。
8. 最后做结构、结果同步、引用、日志和 PDF 视觉检查。

## 3. 逐问覆盖清单

清单为 JSON，每问包含八个可审计字段：

~~~json
{
  "questions": [
    {
      "id": "Q1",
      "title": "本问实际任务",
      "start_label": "mcm-q1-start",
      "end_label": "mcm-q1-end",
      "section_titles": ["能定位本问正文块的标题正则"],
      "evidence": {
        "problem_data_basis": ["题面或数据入口的正文定位"],
        "variables_scope": ["变量、样本单位或口径定位"],
        "mathematical_relation": ["公式、约束或推导定位"],
        "solver_implementation": ["算法步骤、停止条件或代码接口定位"],
        "result": ["结果表、图或关键数字定位"],
        "interpretation": ["数值方向、机制或决策含义定位"],
        "validation": ["回代、基线、滚动验证、残差或独立核验定位"],
        "boundary": ["适用范围、未确认项或因果边界定位"]
      }
    }
  ]
}
~~~

`start_label` 和 `end_label` 用于从编译后的 `.aux` 读取本问首尾页，`section_titles` 用于从 TeX 中定位本问所属标题块。每个起止标签必须各出现一次，位于 `mcm-body-start` 与 `mcm-body-end` 之间；清单顺序须与正文顺序一致，任意两问不得交叉或嵌套。标题正则应覆盖本问实际小节，但不能跨入其他分问。`evidence` 字段值是本问标签区间内应能检索到的短语或正则，不是待填句子。以下情况允许合并，但须在 `waivers` 中说明：

- 题面关系直接列式，本问不需要候选比较；
- 后问完整沿用前问求解器，只新增参数或约束；
- 纯证明问没有数值结果，但有命题结论和反例/边界；
- 当届不允许或数据不足以做某类验证，只能给同源检查并降低结论。

逐问清单只作内部审计。正文不得连续出现“数据入口—变量—关系—求解—结果—解释—检验—边界”八个同名标题。

编译后运行：

~~~bash
python scripts/audit_content_density.py main.tex \
  --aux build/main.aux --coverage coverage.json \
  --problem-type A --format text
~~~

报告把 `table` 浮动体与内部 `tabular/tabularx/longtable` 分开计数，避免一张表被重复当成两张。每问的 `action_distribution` 给出互斥主功能及可加总篇幅，`action_evidence` 允许同一段同时承担模型、求解、结果和检验；前者用于观察重心，后者用于检查动作是否出现。段落、公式和图表数量用于定位薄弱分问，不设统一硬下限；不同题型、不同分问本来就可能轻重不均。

## 4. 题型展开位置

### A 类

有效篇幅主要来自坐标系、机制假设、守恒关系、边界/初值、无量纲化、离散格式、稳定性/收敛、事件定位、误差传播和物理回代。图应承担几何、场分布、轨迹、网格或误差判断。

### B 类

有效篇幅主要来自变量域、目标会计、硬软约束逐条来源、状态转移、可行域、精确基线、小实例、算法编码/修复、停止预算、方案表、约束余量、多目标取舍和策略切换。

### C 类

有效篇幅主要来自记录粒度、字段语义、缺失/重复/异常数量、标签来源、数据划分、描述性图表如何改变模型、基线、特征工程、模型公式、训练/校准、指标、误差分层、结果解释、预测到决策接口和外推边界。

## 5. 扩写与压缩规则

### 允许扩写

- 补此前省略但代码实际使用的变量、约束、边界和参数来源；
- 展开真实推导、离散或状态更新，使公式能从题意走到实现；
- 报告实际运行过的基线、失败试算、消融、敏感性和误差分层；
- 增加能改变判断的图表，并解释异常、转折、活跃约束和方案切换；
- 写清跨问传量、模型版本和结果文件接口；
- 把“模型有效”改为具体检验对象、指标、数值和有限结论。

### 禁止扩写

- 重复题面、竞赛背景、社会意义和算法发展史；
- 从教材搬运与当前变量无关的通用原理或伪代码；
- 虚构候选模型、失败过程、实验、引用或显著性；
- 每问重复相同的“首先—其次—最后”或八项覆盖顺序；
- 用相同结果拆成多张表，或逐格复述已经清楚的表格；
- 用 `\newpage`、`\vspace`、大标题、放大字号、行距或空白达到页数。

### 超页压缩

正文只保留裁决所需结果。完整参数表、所有国家/时段/方案、代码、日志、额外图和中间迭代移到附录；合并重复定义和相同口径的表；不删模型选择依据、关键推导、约束来源、结果解释或验证边界。

## 6. 验收门

正式长稿同时满足：

- 实际正文页数处于用户指定范围，默认 25--30 页；
- 每个分问的八类接口全部命中，或存在具体且合理的 waiver；
- 每个分问均有唯一、按清单顺序且互不重叠的起止页和正文标题块；人工复核其实际页数、段落、有效公式、图表与结果解释是否与任务难度相称；
- 正文强制分页命令不超过确有版式理由的数量；不得出现大段 `\vspace` 或人为调大行距；
- 模型建立、求解、结果与检验合计构成正文主体，背景、重述和通用评价不是主要增量；
- 重复或近重复段落、低信息短段和版式填充信号已经裁决；不能以图表堆叠、同义改写或无信息说明补足页数；
- 附录不计入正文页数，完整代码和全量表格仍然存在；
- 结构审计、结果同步、编译日志和 PDF 抽查全部通过。

上述每一条都必须由带全部参数的审计器给出。`audit_content_density.py` 缺 `--aux` 时
不读页码、缺 `--coverage` 时不核对逐问接口，两种情况下报告写 `coverage=partial`
并逐条列出 `[SKIPPED]`；此时的 `errors=0` 只说明它检查过的那部分没问题，不能当作
页数或覆盖达标。同理，只跑其中几道门不构成长稿验收：`run_longform_portfolio.py
run-gates` 会按 `REQUIRED_RELEASE_GATES` 全集判定，缺任一门即 `GATES_FAILED`。
先启用本模式、放好 `mcm-body-start` 与 `mcm-body-end`、建好覆盖清单，再谈页数；
跳过这三步时 `audit_competition_length.py` 根本无法运行，而其余审计器仍会给出
看起来正常的 `PASS`。

59 篇语料全篇中位数为 45 页，附录跨度中位数为 16 页，正文约 29 页只是解释 25--30 页为何可实现，不是要求每篇复制相同章节比例。`audit_content_density.py` 读取 `fulltext-style-stats.json` 给出的章节四分位只作方向性软提示：它可以提醒背景偏长、求解偏薄等异常，但不能变成固定比例或自动扩写指令。具体统计仍以 [paper-structure.md](paper-structure.md) 和 [fulltext-language-analysis.md](fulltext-language-analysis.md) 为准。
