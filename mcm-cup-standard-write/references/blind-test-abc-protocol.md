# A/B/C 长稿前向测试协议

## 两级测试不能混称

`scripts/test_longform_abc.py` 是快速回归门。它用未引用获奖论文原句的短样稿分别检查三类题最容易被统一文风抹掉的接口：A 题的机理、边界、离散与误差，B 题的变量域、约束来源、可行性与策略切换，C 题的记录粒度、集合隔离、校准与结果解释。它可以在 Skill 改动后立即发现题型退化，但不等于三篇完整竞赛论文。

完整盲测是另一层：选取未进入当前写作提示的真实题目和数据，从读取附件、建模、运行代码到生成 25--30 页正文全部前向完成。完整盲测必须保存题面版本、代码、运行命令、结果清单、覆盖清单、编译产物和人工裁决记录。只有实际完成这一层，才可以说相应题型通过正式长稿盲测。

## 快速回归门

每次修改长稿、题型或语言规则后运行：

~~~bash
python scripts/test_longform_abc.py
~~~

正例必须同时满足：

- `audit_manuscript.py` 没有结构性 error；
- `audit_content_density.py` 能定位正文和逐问页码、段落、公式及图表；
- 题型专属四类接口全部出现，且方法名以前有本题事实、方程、边界或数据依据；
- A/B/C 三份样稿使用不同的事实入口和段落推进，不把 C 题的数据分析节奏复制给 A、B 题。

反例故意只写“问题复杂，因此采用某模型”。若题型接口检查仍通过，说明回归门失效。

## 完整盲测验收

每个题型单独记录：

1. 题目和附件是否未进入本次检索提示；
2. 正文是否实际处于要求页数范围；
3. 每问的页数、段落、公式、图表、解释和检验是否与任务相称；
4. A 题是否能从机制走到边界、离散和误差，B 题是否能从变量域走到可行方案和策略变化，C 题是否能从记录口径走到隔离验证和有限解释；
5. 代码、图表、结果文件与正文是否由同一次运行生成；
6. 队员能否逐段复述“为什么这一段在这里、这一选择依据什么、结论到哪里为止”。

现有三份正式记录分别为：`blind-test-2019-cumcm-a.md`、`blind-test-2018-cumcm-b.md` 和 `blind-test-2025-mcm-c.md`。三稿均完成独立求解、25 页正文、编译、内容密度、结果同步、复现清单和数学语义闭环；它们证明当前工作流在这三道陌生题上跑通，不证明未来所有 A/B/C 题都会自动合格。

正式盲测出现过两类快速样稿难以暴露的问题。A 题曾发生“短窗口选参、长窗口报告”和离散事件造成的虚假末位精度；B 题曾发生并发资源共用时钟、跨班动作未截断以及目标打平被误写成策略等价。后续完整盲测必须主动检查这些运行时边界，不能只数章节、页数和公式。
