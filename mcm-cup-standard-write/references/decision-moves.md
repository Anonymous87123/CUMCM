# 公开判断轨迹动作库

## 用途

这份资料约束“题目到模型”之间的可见论证，不要求也不输出模型的隐藏思维链。它记录的是论文作者可以公开承担的判断：看到了什么、哪一处改变了建模对象、保留或放弃了什么、结论到哪里为止。

每个分问先选一个最贴近当前证据的主动作，必要时再接一个不同功能的动作。动作不是八段式模板，也不是必须按编号顺序出现；若题面关系可以直接列式，直接列式就是合格的短路径。没有实际试算、候选比较或失败过程时，不得补写“经过比较”“验证了方案”之类的经历。

## 动作表

| 动作 | 适用触发 | 正文应公开的内容 | 不要写成 |
| --- | --- | --- | --- |
| 记录粒度改职责 | 运动员、订单、个体、项目等记录不能直接作为目标表 | 记录单位、重复键、目标表和辅助表分别承担什么责任 | “先清洗数据，再建立模型” |
| 量级观察改边界 | 数值范围、数量级或极端值会改变近似、网格或搜索范围 | 观察到的量级、它排除了哪种处理、留下什么边界 | “数据较大，因此采用复杂算法” |
| 现象追问机制 | 图表出现拐点、跳变、异常或反常方向 | 先报告现象，再检查局部轨迹、约束、事件或同时间比较 | “结果符合预期，说明模型有效” |
| 基线承担解释 | 复杂模型和简单基线都能给出结果 | 基线解释的部分、解释不了的部分，以及保留它作为参照的理由 | “比较多种模型后选择最优模型” |
| 候选接近时保留简单者 | 候选误差接近、复杂度或可复现性不同 | 同口径指标、复杂度/边界差异、最终保留的接口 | “综合考虑后选择更优方案” |
| 方程关系先于算法 | 题面已给几何、守恒、平衡或转移关系 | 关系如何变成变量、约束或递推，算法只在关系落地后出现 | “采用某某算法求解上述问题” |
| 事件切换解释跃变 | 参数小改造成输出不连续或首次事件改变 | 变化前后的触发对象、局部结构、为何不能用连续敏感性解释 | “参数敏感，结果变化明显” |
| 搜索口径回到报告口径 | 搜索窗口、回放窗口或尾部统计窗口不同 | 哪个窗口负责选参、哪个负责最终裁决；若不一致，统一口径后重新搜索 | “经优化得到最优参数” |
| 相邻候选裁决末位 | 离散开关、阈值或网格使目标在窄区间跳变 | 最终候选、两侧邻点、首次改变的事件以及可报告有效位数 | 把搜索器长小数当成连续物理精度 |
| 前问接口冻结 | 后问沿用前问变量、预测或状态 | 明确哪些量不再重建，只新增哪些参数、目标或约束 | 每一问重新介绍完整模型 |
| 约束后果推出下界 | 小参数、短路径或大规模方案会造成不可行动作 | 现实动作后果、对应数学不等式、取值下界和边界解释 | “根据经验设置下限” |
| 结果回代裁决 | 近似、代理目标、降维或初值需要完整模型接管 | 近似只承担什么任务、何时回到完整目标、回代读数如何裁决 | “降维提高效率并保证精度” |
| 误差分层而非总分 | 总体指标被零值、强类别或大样本掩盖 | 主体子集、局部误差、总体误差各自回答什么问题 | 只报告一个平均误差 |
| 并发资源拆时钟 | 一台设备加工时另一资源仍能清洗、移动或等待 | 各资源何时被占用、哪个动作可并发、事件完成后谁先更新 | 用一个总时钟顺序执行所有动作 |
| 报告边界截断动作 | 最后一个移动、服务或清洗跨越班次/仿真终点 | 产量计入条件、动作日志终点、忙碌和等待的截断规则及时间会计 | 让最后一个完整动作把利用率推过 100% |
| 目标打平后保留差异 | 两条策略目标值相同但路径、动作或资源占比不同 | 相同的指标、仍不同的状态序列和不能推出的等价结论 | “结果相同，因此两种策略等价” |
| 直接损失追到传播损失 | 故障既报废当前物料又推迟后续事件 | 报废件数、停机时长、班末少完成量分别计数，并解释传播路径 | 把产量损失直接等同于报废数 |
| 证据不足主动降级 | 缺少身份、时间、对照、外部标签或完整赛程 | 能确认的候选/情景、不能确认的因果或外推、后续核查入口 | 末尾补一句泛化的局限性 |

## 写法选择

1. 先在草稿区写 `观察/限制 -> 改变的对象 -> 数学落点 -> 公开结论边界` 四个内部字段；字段为空就删掉，不把表格原样搬进正文。
2. 从全文检索中选择同题型、同章节、同动作的 3--8 个真实段落，观察它们从事实进入公式、图表或结果的位置。只借鉴动作和节奏，不复制原句、数字或模型。
3. 一节内允许短句、长段、公式后解释和图表前判断交替出现。连接词随事实顺序自然变化，不能每问都使用“首先—其次—最后”或“核心困难—基线—不足—候选—选择”。
4. 若候选比较没有真实记录，改写为适用边界或直接列式；若只有同源回代，称为同源检查，不称外部验证；若只有残差情景，称为候选或情景，不称因果贡献。

## 交付前检查

- 每个分问首次出现模型名以前，至少有一处本问题面、数据、方程、前问接口、真实读数或现实后果。
- 判断动作应能指向一个公式、图、表、日志、结果文件或明确的有限结论。
- 不用动作库制造失败试算、候选数量、全局最优、显著性或稳健性。
- 同一稿中至少出现两种不同的段落推进方式，但不为追求变化而替换事实顺序。
