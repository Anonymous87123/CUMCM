## 1. 四份源文件的职责边界

### `assignment.tex`

- 用于说明 59 篇、2892 页语料范围、OCR 与人工门禁、A/B/C 题型归纳、成员算法学习、四周计划和 Skill/模板成果。
- 它回答“学了什么、证据从哪里来、训练如何安排”，不是赛中正文骨架。
- 可复用其中已经核实的语料统计、章节篇幅和训练分工；不得把研究方法、OCR 日志或五十九篇总表搬进竞赛论文。
- 需要更新学习报告时，以该文件现有内容为基线增量修改，不另造同义报告。

### `submit.tex`

- 用于课程提交：精简学习笔记、A053 单篇一等奖论文分析、本队论文模板和竞赛规章。
- 其中的 `\slot{}`、任务表、假设表、模型卡、结果/检验/灵敏度账本适合教学和赛前填充。
- 正式比赛时不得直接提交整份课程作业；只把已经填实、确有必要的结构迁入正式模板。
- 表中的占位提示是准备材料的工具，不是正文固定句式。填完后应把多数账本转为自然叙述或附录记录。
- `submit.tex` 不再提供可逐句替换名词的整段成品句架；检验判据等内容先记入账本，正文只呈现本题实际发生的裁决。

### 根目录 `main.tex`

- 只作为上游培训材料：可借摘要检查、图表规范、数据处理、算法参数、AI 使用记录、复现清单和交稿红线等组件思想。
- 其中的 `XXX`、通用推荐句、固定“理由链”、创新公式和风险分级均不是 59 篇论文统计结论。
- 不复制其中的机械箭头链，不把“模型性质 -> 算法性质 -> 选择理由 -> 改进点 -> 验证”写成正文顺序。
- 与正式规则、实测语料或 `thesis template/main.tex` 冲突时，本文件优先级最低。

### `thesis template/main.tex`

- 这是唯一的正式竞赛模板源，继续使用现有 `cumcmthesis.cls`、字体和带空格的 `thesis template/` 路径。
- 指导模式显示 `\MCMGuide` 七项说明和按需账本；提交模式由 `\MCMSubmission` 关闭全部指导内容并切换为黑白打印。
- 指导模式用于发现缺证据、缺接口和缺核验，不要求每张表都进入论文。
- 修改模板时保留类文件、字体、模式开关、标题接口和现有用户内容；不新建 `thesis-template/`，不把 `example.tex` 改成主模板。

## 2. 冲突时的优先级

1. 当届官方赛题、附件和最新竞赛规章。
2. 本队真实数据、代码、日志、图表、结果和人工核验记录。
3. `contest-rules-2026.md` 中已经核读的规则；规则变化时重新核读原文件。
4. `thesis template/main.tex` 的类、模式和正式章节结构。
5. `submit.tex` 的课程交付范围和简版填写组件。
6. `assignment.tex` 的语料统计与学习报告事实。
7. 根目录 `main.tex` 的培训组件。

模板不能推翻证据：模板中出现某模型、检验、图表或句子，并不授权在当前论文中声称已经做过。文风由编号论文证据控制，模板本身不能进入“人类作者高频写法”统计。

| 交付物 | 应使用的源结构 | 必须保留 | 必须剔除 |
| --- | --- | --- | --- |
| 完整学习报告 | `assignment.tex` | 语料边界、分工、算法学习、论文分析、计划和核验状态 | 竞赛正文占位符、赛中虚构结果 |
| 课程学习结算 | `submit.tex` | 精简学习单元、指定单篇分析、本队模板、规章 | 59 篇逐篇长表、过度展开的算法教材内容 |
| 赛前指导模板 | `thesis template/main.tex` 指导模式 | 七字段指导、按需组件、篇幅证据、规则提醒 | 虚构的已完成结果 |
| 正式竞赛稿 | `thesis template/main.tex` 提交模式 | 正式章节、实际 AI 声明、引用、附录与复现信息 | 指导框、占位符、教学表、目录、身份信息 |

不能只因用户说“写论文”就默认生成课程报告，也不能把 `submit.tex` 的“本队论文模板”误当作正式投稿文件。先从目标文件、任务描述和编译模式判断交付物；仍不明确时，先完成不依赖该选择的证据整理，再向用户确认。

## 4. 正式模板的固定主干

正式竞赛稿按下列主干组织，但允许把结果和检验放入相应分问内部：

1. 摘要与关键词。
2. 问题重述。
3. 问题分析。
4. 模型假设。
5. 符号说明。
6. 分问题模型建立与求解。
7. 结果分析与模型检验。
8. 灵敏度或稳健性分析，仅在真实扰动、情景或决策稳定性检查存在时保留。
9. 模型评价与改进。
10. AI 工具使用声明，按实际情况采用官方要求的一种表述。
11. 参考文献。
12. 附录：代码、数据、补充结果和运行说明。

标题写实际任务，不把算法名当标题。下一问开头说明沿用的变量、参数、状态、筛选结果或计算核，以及本问新增、删除或放开的部分。

## 5. 指导模式和提交模式

### 指导模式

- 每级标题下的 `\MCMGuide` 依次检查目标、必备清单、语言风格、篇幅排版、图表位置、高分点和错误警示。
- 指导框只给检查问题，不替作者填写答案。
- 账本只在存在真实取舍、事件切换、字段歧义、模型修正或证据缺口时使用。
- 可以把账本留在训练稿中；转正式稿时，只保留评阅者理解和复算所需的信息。

### 提交模式

- 定义 `\MCMSubmission` 后，`\ifmcmguidance` 必须为假，全部指导框、示例、空账本和关键词占位隐藏。
- `\MCMNoAI` 与 `\MCMUsesAI` 必须保留且只保留一个；启用 `\MCMUsesAI` 时还必须定义非空的 `\MCMUseDescription`。漏选、双选、缺用途或空用途均应中止编译，不能让声明占位文字进入 PDF。
- 使用黑白打印类选项，正文不设目录，不出现队员、学校、赛区等身份信息。
- 摘要、正文、AI 声明、参考文献、附录和支撑材料依当届规则排列。
- 提交前搜索 `\slot`、`XXX`、`待填`、`示例`、空 caption/label、双份 AI 声明和未删除的训练说明。

## 6. 组件库按触发条件选择

下面是正式模板中按需表格和段落的语义归并。每个组件都有触发条件；没有对应证据就不启用。内部表可以保留完整核对项，正文只呈现与当前判断有关的部分。

### A. 任务与定义接口

| 组件 | 何时启用 | 最终交付 |
| --- | --- | --- |
| 分问任务矩阵 | 多问之间传量、改变目标或增加约束 | 每问输入、输出、硬约束、传递量 |
| 直接量与唯一剩余量 | 题面公式可直接求出大部分量 | 已知量消去过程和真正未知量 |
| 竞争定义裁决 | 一个术语确有两种合理解释 | 同一数值例、区分证据、保留口径 |
| 缺失字段语义 | 空白可能代表零、未知或未采样 | 分字段处理和受影响样本范围 |
| 观察/纳模范围 | 发现规律但不一定需要纳模 | 是否纳模及其对结论的影响 |
| 目标变化重审 | 后问目标方向改变 | 恢复或删除的候选范围与理由 |

### B. 机理、几何与事件组件

| 组件 | 何时启用 | 最终交付 |
| --- | --- | --- |
| 物理选根与局部递推 | 方程多根、构件有先后或方向 | 候选根、过滤条件、最近可行根 |
| 首次事件缩域 | 碰撞、失效、越界或触发事件 | 不漏检证明、候选对象、终止状态 |
| 越界回退与误差界 | 变步长、二分或事件定位 | 前进、回退、缩步、停止阈值及物理误差 |
| 固定量与齐次缩放 | 后问可能无优化自由度或可比例复用 | 不变量证明、复用条件、符号和边界变化 |
| 完整分类与等价压缩 | 相对次序、拓扑或分支较多 | 原始覆盖、等价关系、保留分支 |
| 工程简化与二值判定 | 精确几何代价过高 | 规模依据、补偿条件、代理判据和适用范围 |
| 空间证据到布场 | 云图、方向或空间结构改变设计 | 图中读数、移动方向、变量区间 |
| 局部/全局信息分离 | 对象只能获得局部信息 | 可见量、禁用量、局部目标、事后评价 |

### C. 计算核与求解选择

| 组件 | 何时启用 | 最终交付 |
| --- | --- | --- |
| 候选模型试算与换路 | 真实试算或边界确实排除旧路 | 同口径证据、局部修改和保留部分 |
| 数据能力与方法降级 | 短序列、缺对象、无趋势或强随机 | 降级方法、时窗和结论边界 |
| 变量结构到求解器 | 连续、整数、混合或多目标结构改变 | 变量域、规模、所需求解能力 |
| 固定变量与一维搜索 | 其余量可冻结且图形支持单峰/单调 | 固定量、快速核、区间和停止条件 |
| 粗定位与精化 | 全域精搜代价高 | 粗阶段交付区间，精阶段交付精度 |
| 抽样预算与弱变量冻结 | 函数评估预算受限 | 抽样比例、重复、影响量和冻结依据 |
| 预处理误差与收益 | 近似、网格或代理模型用于加速 | 与高精度基准的误差及计算量变化 |
| 结构复用和退化检查 | 前问模型沿用或结构变换 | 复用接口、退化条件和修复动作 |

### D. 数据、预测与决策组件

| 组件 | 何时启用 | 最终交付 |
| --- | --- | --- |
| 数据侧写到决策接口 | 探索图会改变变量、窗口或约束 | 每张图回答的问题及下游接口 |
| 数据病态与方法切换 | 零膨胀、偏态、共线、异常或重复 | 病态证据、变换/分流、样本边界 |
| 业务记忆与模型阶数 | 时间序列或动态决策 | 记忆证据、窗口/阶数、初值来源 |
| 数据--预测--决策谱系 | 预测输出进入优化或行动 | 字段、清洗、特征、标签、划分、概率、决策 |
| 潜变量与可观测代理 | 业务概念不可直接观测 | 代理含义、方向、归一化、权重和限制 |
| 系数与特征语义 | 回归或人工特征需要解释 | 单位变化、业务含义和下游用途 |
| 指标门控 | 指标决定是否预测、筛选或回退 | 实际值、阈值、动作和未入选对象去向 |
| 预测--优化状态接口 | 多期或滚动决策 | 本期输入、动作、实现量、期末状态、下期初值 |
| 现有数据/外部证据分流 | 当前附件不能区分竞争机制 | 已有结论、待采数据、预期裁决 |

### E. 结果、检验与稳健性组件

| 组件 | 何时启用 | 最终交付 |
| --- | --- | --- |
| 同期历史或共同环境基线 | 比较候选方案 | 同口径条件、绝对量、相对量和裁决 |
| 诊断表导读 | 有统计量、残差或多行检验表 | 行列含义、阈值、有限结论和修正 |
| 异常数值业务语义 | 负预测、跳变、局部尖峰或极端值 | 异常区间、机制、决策动作和影响范围 |
| 独立规则交叉核对 | 主模型外有不同来源的规则 | 一致与不一致对象、裁决范围 |
| 结构预言式检验 | 机理会预言峰值、对称轴或迁移方向 | 改动输入、重算结果、结构是否随之变化 |
| 随机重复与代表方案 | GA/PSO/抽样等含随机性 | 种子、重复、分布、典型方案选择规则 |
| 硬阈值余量 | 方案可行但仍有优化空间 | 各约束余量和继续优化的实际收益 |
| 灵敏度范围/方向/饱和 | 参数误差或决策切换值得检查 | 基准、扰动来源、固定量、输出和切换点 |

### F. 评价、改进与复现组件

| 组件 | 何时启用 | 最终交付 |
| --- | --- | --- |
| 模型边界到补充数据 | 局限来自对象、时窗或数据缺口 | 具体缺口、受影响结论、补采和验收指标 |
| 新增实验的证据缺口 | 允许补充有限实验 | 每个实验要裁决的疑问和分支规则 |
| 控制变量双响应 | 需要比较单一因素 | 保持条件、唯一改变量、可比组和各响应 |
| 评价与改进账本 | 已识别误差源或计算限制 | 公式/数据支撑的优点、局限、修改层和复验 |
| 附录复现清单 | 所有正式稿 | 数据字典、入口、依赖、参数、随机性、中间结果、命令和输出 |

不要为“全面”把这些组件全部放进正文。全面是关键判断不漏项，不是表格数量多。若一个组件只服务内部核对，可以不渲染；若主文需要结论但证据表过长，主文保留裁决行，完整表放附录或支撑材料。

## 7. 人类建模判断的公开方式

论文必须让读者看见模型为何成立、何处发生选择、结果为何可信，但不输出模型的隐藏思维链，也不表演一串整齐的元步骤。

### 内部记录

写作前可按需记录以下事实：触发材料、受限旧路、实际改变、结果或边界。四项不要求齐全，也没有固定顺序。它们只用于确认没有模型空降、虚构候选或结论越界。

### 正文呈现

- 从当前真正出现的入口开始：图表读数、方程性质、现实后果、同口径试算、计算负担或前问接口。
- 选择依据放在证据实际出现的位置。它可能位于问题分析、公式前后、算法入口、结果图后或下一问开头，不集中写成一份“选型过程”。
- 公式前交代关系来源，公式后解释新增量或每一项在当前问题中的作用；不重复教科书定义。
- 结果后解释方向、数量级、约束状态、局部机制和结论边界。表格已经给出的数字不逐格复述。
- 没有比较过候选就不写“比较多种方法”；没有失败试算就不写“原模型效果不佳”；由硬约束直接决定的方法无需补造基线。
- 段落在完成当前判断后停止。不是每段都要凑齐事实、选择、动作、结果和边界。

### 禁止外显的机械结构

- 不写“核心困难 -> 基线方案 -> 基线不足 -> 候选比较 -> 选择依据 -> 模型建立”。
- 不把“观察 -> 判断 -> 动作 -> 结果 -> 边界”作为所有段落的固定句序。
- 不让每一问都出现一轮“先否定、再改进、后验证”。
- 不用“首先、其次、再次、最后”包装本来没有并列关系的内容。
- 不把模板字段名直接写成段首，如“选择依据是”“模型边界是”“创新点是”。
- 不用连接词轮换器伪造节奏；`注意到`、`考虑到`、`由图可见` 后必须有本题对象和可定位依据。

### 写后识别机械痕迹

1. 比较相邻三个段落的首句、句长和信息顺序；结构可互换时重写。
2. 暂时删去对象名和数字；若段落仍可无损套入另一道题，说明内容过于模板化。
3. 圈出模型名；附近必须有授权它的变量域、图形、方程性质、规模或边界。
4. 圈出被舍弃的方法；必须有真实推导、试算、规则或数据证据。
5. 检查篇幅增长是否来自推导接口、口径、约束、结果解释和检验，而不是重复算法原理。

## 9. 执行流程

1. 判定交付物和模式，读取对应源角色。
2. 核对当届规则、赛题、附件和现有稿件，冻结不可改的公式、数字、标签与引用。
3. 建立分问输入/输出/约束/传递量矩阵。
4. 依据实际证据选择最少的模板组件；未触发的组件不加载到正文。
5. 从 `style-pass2-all-papers.md` 找相同判断动作，再回 `human-style.md` 核对原页证据和适用边界。
6. 按 `natural-reasoning.md` 选择自然入口，先写模型/求解和结果/检验，再反写摘要、评价和重述。
7. 将内部账本压成自然段，只留下会影响模型和结论的公开判断。
8. 指导模式检查七字段；提交模式清除全部提示、示例、空表和占位符。
9. 运行 `audit_manuscript.py`、XeLaTeX 编译、引用/标签检查和从零复现。

## 10. 验收门

- 交付物类型、模板源和编译模式明确。
- 每个进入正文的组件都有当前题证据，每个关键判断能定位到题面、数据、公式、图表或日志。
- 正文不存在统一的五步/六步理由链，连续段落不共享同一骨架。
- 模型名没有空降，被舍弃路线没有虚构，篇幅不靠算法百科扩充。
- 指导版保留可操作检查；提交版不含提示、占位、教学文字或身份信息。
- 正文公式、代码接口、结果表、摘要数字和附录文件相互对应。
- 模板统计只按 59 篇语料的当前证据口径引用：2892 页已重建为正文段落，篇幅、章节、功能词和公开动作统计见 `fulltext-style-stats.json`；公式、表格与小字号图注仍以原始栅格为准，不把 OCR 文本用于数值核对。
- 不声称“完全模仿人类”“保证一等奖”或“规避检测”；只说明采用了可定位的人类论文动作、模板组件和质量门。
