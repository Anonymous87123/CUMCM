## 可调用的模型与写作动作

1. `业务含义 -> 不可直接观测 -> 可观测代理 -> 指标方向 -> 归一化 -> 权重解释`：潜变量不能凭概念打分。
2. `方便代理 -> 两个不重复的反对理由 -> 更符合机制的替代口径`：方法选择必须写清为什么不取历史均值。
3. `初始结果不合预期 -> 目标量级/业务机制诊断 -> 保留未受影响模块 -> 局部加约束重算`：允许模型经历一次真实修正。
4. `本周订购 -> 本周转运 -> 实际到货/消耗 -> 库存更新 -> 下一周初值`：动态模型要写状态怎样传递。
5. `全周期轨迹 -> 指名局部周次 -> 上一期状态 -> 具体供应商机制 -> 局部裁决`：宏观和微观证据不能互相替代。
6. `方向正确 -> 量化幅度 -> 承认效果有限 -> 约束/可行域原因`：禁止把小改进包装成“显著提升”。
7. `本问修改什么 -> 下游模块输入/目标是否改变 -> 复用或更新裁决`：跨问继承按接口解释。
8. `二元筛选 GA / 逐周订购 GA / 规则式运输分配`：同篇的不同求解器必须分别说明变量、约束和输出。

## 人类惯用词及段落骨架

- `由于……无法由附件中的数据直接得出，故引入……这一概念`：承认观测缺口后再造代理。
- `构造……三个指标来衡量……；对于……为成本型指标；对于……为效益型指标`：代理、方向和处理方法连续出现。
- `本文认为不应该直接以……作为……。主要原因有两点：首先……；其次……。因此……`：拒绝方便方案时给足理由。
- `然而我们并未发现……。这是因为……往往会掩盖……的现象`：从不合预期的结果转入机制诊断。
- `对于实施效果，本文从宏观和微观两个角度……`：整体趋势后再解释具体周次。
- `尽管其中出现了……但值得注意的是，在下一周……马上回归……`：异常、反馈和解释顺序清楚。
- `新方案虽然对……起到了……的效果，但效果并不显著。对此，本文认为……因此……故而……`：承认弱效应并给边界原因。
- `该模型的输入为……，总是以……为目标……因此不需要作出更新`：从接口与目标论证模块复用。

起草时只复用信息顺序；必须填入实际指标、周次、约束、幅度和业务机制，且避免在相邻段落重复同一转折词。
