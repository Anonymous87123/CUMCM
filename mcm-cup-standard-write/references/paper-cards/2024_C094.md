## 实际模型链

`Excel 空格清理与地块分区 -> 作物适宜性及季次解释 -> 亩产/成本/售价三维表 -> 边际收益与性价比排序 -> X 连续面积 + Y 二元选择 + Z 实际销量 -> 滞销/半价两类目标 -> 面积、销量、连作、三年豆类、地块季次、适宜性和管理 p/q 约束 -> Gurobi MIPGap 0.01 -> p/q 候选的收益--管理取舍 -> Gurobi 与贪心同口径对照 -> 贪心豆类补种、性价比选择、超量重排和状态更新 -> 时间/情景维度 -> 100 个随机序列生成 100 个候选策略 -> 每个候选在同一批 100 个环境中交叉复算 -> 按收益均值裁决 -> 按性质、用途、营养和耕作要求筛替代候选 -> 替代因子与替换前后目标复核 -> 豆类轮作亩产 +1%、协同收割单位成本 -1% -> 需求--价格--成本方向关系 -> 问题三沿用问题二并加入新增接口 -> Gurobi/Python 附录实现`

## 结果与检验摘录

- 问题一求解器报告：滞销口径 40,244,799.20 元，半价口径 56,325,297.78 元；贪心路线分别为 36,848,378.08 元和 46,724,871.84 元。正文把差异写成收益与计算速度的取舍，而非只报“各有优点”。
- 管理参数网格给出滞销情形 `p=3,q=8`、半价情形 `p=3,q=3`；表后同时交代“地块种类上限”和“单作物分布地块数上限”的含义。
- 问题二先生成 100 个随机变量序列和 100 个候选策略，再把每个候选放回同一批环境中复算，论文报告均值 51,667,432.02 元。
- 替代试算把小麦换谷子、青椒换辣椒分别经过候选性质筛选和收益复核；正文给出的两组目标变化为 `40244799.1993 -> 39210519.8953` 与 `40244799.1993 -> 40203379.8178`。
- 互补关系被拆成两个接口：豆类轮作修正单位亩产为原值的 1.01 倍，同机收割修正单位成本为原值的 0.99 倍；没有把二者笼统合并成一个“协同系数”。
- 问题三沿用问题二主体约束与交叉复评，只加入替代、互补及需求--价格--成本关系；p.20--21 报告 53,078,389.86 元，并与问题二 51,667,432.02 元按同一口径比较。摘要 p.1 另有独立印刷数值，本文按页码保留来源边界，不将其混并成新的复算结果。

## 人类文风与判断轨迹

1. 先解释哪些作物能在何种地块和季次种植，再写变量域；现实适宜性不是背景段，而是约束的来路。
2. 把“不要太分散”拆成横向 `p` 与纵向 `q` 两个可调参数，在同一张候选表中并列管理负担和收益，再给出取值。
3. 双算法比较保留收益、速度和适用场景的具体数值；作者没有用一个抽象的“综合性能”替代取舍。
4. 贪心算法按程序状态叙述：先查两年豆类面积，再按性价比选作物；超过预期销量时重算排序，分配后更新剩余面积、需求余量和种植历史。
5. 随机稳健段把“候选生成”和“公平比较”分开：先产生方案，再用统一环境集交叉复评，最后由均值裁决。
6. 替代性先由性质、用途、营养和耕作要求产生候选，再用需求满足和目标变化决定是否进入模型；类别相近并不自动等于可替代。
7. 结果表后用“对象变化 -> 收益幅度 -> 业务机制 -> 决策优先级”推进，不用“结果显著、模型鲁棒”这类空泛结论。
8. 正文变量与附录变量有可回查的接口：`X/Y/Z/Z_excess/Z_rice` 对应面积、是否种植、销量、超量和水稻分支；贪心代码中的 `planting_history`、`remaining_area` 和需求余量对应流程图状态。

## 可迁移句式与去 AI 味

- “如果管理要求不写成可调参数，后续的收益比较就无法说明取舍；因此分别限制……，再在候选表中选择……”
- “求解器在当前可行域内给出较高收益，贪心策略则维护需求余量和种植历史，计算更快；两条路线分别适合离线规划和需要快速调整的情形。”
- “随机序列先用于形成候选方案；为避免每个方案只在自己的环境中被评价，再将它们放回同一组环境中交叉复算。”
- “类别相近只能说明存在替代可能，只有替换后仍满足原需求且目标变化处于可接受范围，才把该关系写入模型。”
- “轮作影响的是单位产量，同机作业影响的是单位成本，二者对应不同的经济量，不能合并成一个没有对象的协同系数。”
- 删除“综合考虑多种因素”“采用优化算法提高鲁棒性”“结果更加合理”等套语，改写为具体对象、数值、动作和后果。
