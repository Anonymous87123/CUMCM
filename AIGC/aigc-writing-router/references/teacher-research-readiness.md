# 教师研究稿压力测试

附件中的 IEEEtran 草稿被当作“研究稿完整性压力测试”，不作为获奖论文文风样本，也不作为英文表达正例。它的价值在于把改写前经常被忽略的内容责任写得很直白：摘要必须说明研究对象、问题和结果；贡献列表不能只留下标题；理论、方法、实验、分析和结论不能停留在空的章节壳；模板中的作者、致谢、页眉和收稿日期必须清除；公式、标签和内部引用要形成可追踪的闭环。

## 进入改写前

对 `research` 和 `academic-en` 的 TeX，先执行：

```powershell
python scripts/audit_research_draft_readiness.py MAIN.tex --format json
```

只要报告为 `BLOCKED_CONTENT_INCOMPLETE`，就回到内容阶段补齐研究问题、贡献、证明/理论、实验结果或结论。Humanize 不承担补写实验、不承担猜测作者意图，也不能把 IEEE 示例文字改成看似完整的论文。

## 草稿的公开责任

研究正文可以公开说明：问题为什么值得研究，现有分解或基线在什么条件下失效，本文的定义/模型要解决哪一处缺口，实验怎样对应问题，结果支持到哪一级，哪些只是特定设定下的经验判断。这里记录的是读者可以检查的论证关系，不是模型的隐藏思维链。

## 模板残留

以下内容一律当作结构残留处理：`IEEE Publication Technology`、示例作者与致谢、示例页眉、示例收稿日期、`TODO/TBD/FIXME`、重复 `label`、悬空 `ref`，以及“主要贡献如下”后没有实际贡献条目。修复时应回到事实和推导，不能用泛化句填空。

## 证据边界

该压力测试只说明“是否具备进入一次受保护语言候选的最低载体”。通过不等于研究正确、数学正确、结果可复现、作者为人类或外部检测器会给出任何分数；未通过也不说明原稿文风，只说明当前文件还不适合先做降 AI 润色。
