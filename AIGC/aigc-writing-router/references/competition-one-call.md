# 数学建模比赛一键改稿协议

## 触发

用户已给出或刚刚提到一份 CUMCM/数学建模初稿，并说“调用 AIGC”“用 AIGC 降低机器味”“按 AIGC Skill 改稿”等同义请求时，进入 `MCM_COMPETITION_REWRITE`。这不是只读审计，也不是生成路由计划。除非源文件存在歧义，否则直接完成候选文件、编译 PDF 和相对比较，不要求用户逐条选择工具。

## 默认输入与输出

- 显式路径优先；否则使用对话中最近明确提到的主 TeX。工作区只有一个合理主文件时直接采用；多个候选且无法从 `\documentclass`、`\begin{document}` 和引用关系判断时才询问。
- 权威源只读冻结。候选写入独立目录，目录名包含 `aigc-candidate` 或本轮时间戳；不得覆盖源稿。
- 正常交付至少包含候选主 TeX、递归引用文件、编译 PDF、源/候选 SHA-256、改写范围、未决项和相对比较报告。

## 必须执行的顺序

1. **冻结并读懂稿件**：确定题型、题面、数据、代码、结果文件、主 TeX 和递归输入。题面和数据来自主办方或网络时，同时保存来源 URL/文件、获取日期、原始字节哈希和清洗脚本；不能把搜索摘要当数据。随后运行 `prepare_competition_evidence.py` 建立四类材料台账。
2. **先补齐可复现的模型链**：若代码或结果尚不存在，且用户授权由本 Skill 完成，先由 `$mcm-cup-standard-write` 与 `$deai-modeling-writing` 建立建模工作台，写出 MATLAB/Python 代码并实际运行。固定随机种子、环境版本、运行命令、输入和输出哈希；至少做一次独立数量级、边界或小样本复算。依赖、数据或题意不足时停在 `REVIEW` 并列出缺口，不能用想象的数值填正文。运行结束后用 `audit_repro_manifest.py`，再把复现记录接回 evidence bundle。
3. **先修正文内容组织并建立逐节写作底稿**：利用已运行的代码、表格、图和结果，由 `$mcm-cup-standard-write` 与 `$deai-modeling-writing` 处理全稿。逐问找出题面事实、变量含义、约束来源、试算、边界、前问接口和结果后果；把直接跳到模型、泛泛解释、卡片式标签和算法百科改成围绕这些真实材料展开的正文。生成前对初稿运行工作台 `--phase preflight`，只验证来源、路线记录和分问映射，不能要求原稿已经写好待补的判断桥；候选完成后才以 `--phase release` 核对正文落地。确有结果解释时，在工作台 `interpretations` 中绑定观察项、解释项和代码/结果/图/日志来源；确有检验结论时才给 check 填 `result_terms`，不得从成稿反推一段未实际发生的解释或检验。公开思考过程随本问材料自然出现，不另造固定八步标题。落笔前先运行 `prepare_style_retrieval_plan.py`，为每个可写章节绑定 3--8 个已核验全文段落及相邻上下文；再运行 `prepare_section_authoring_brief.py`，把该节所属分问的本题事实、数学落点、实际路线和真人预审与语料 ID 对齐。语料只学习事实入口、判断动作、公式/图表接口和停止位置，禁止复制句子或移植范文事实；工作台字段也不得按顺序翻成固定段式。两份文件的稿件树哈希、全文索引哈希、工作台/预审哈希和保留论文排除结果随阶段证据保存。
4. **挂接结构工作台**：运行 `run_aigc_adapter.py --package AI_paper --action workbench-plan --document-type mcm`，只激活 MCM 场景下的摘要聚焦、论证结构、引用、表格、图示、提纲与同行审阅单元。它们给内容负责人返回问题位置和修改建议，不运行 `academic-tone-polisher`，不另写第二份语言候选，也不把 GUI/远程能力写成已执行。
5. **只做一次语言候选**：由 `$humanize-academic-chinese` 处理仍显机械的连续正文单元。不得把完整论文交给多个 Humanizer 串洗。词项扫描只决定优先阅读位置；正常术语或承担明确逻辑功能的表达使用位置级 KEEP，不为清零词表强行换同义词。每个正文 span 最多经历一次人文化改写。
6. **回到事实局部重写**：`voice-mode`、`style-rhythm` 或 `$ai-check` 的只读报告定位到真实病灶时，回到该段数据、公式、试算、对象或操作后果重组。不得启动第二个降 AI 工具，也不得只轮换连接词；`$ai-check` 完整保留九类信号和逐条证据，但上游 `VERDICT`、`AI-EDITED FRACTION` 必须在适配报告中删除，不能给作者身份或采用结论。
7. **逐段保留或回退**：对每个改动判断具体性、公开判断过程、内容密度和语义忠实度。候选删弱限制、改错对象、把判断升级成结论、增加无依据因果或只获得同义替换时，回退该段；不能为了证明本次调用有效而保留坏改动。
8. **相对比较和正式门**：运行源稿—候选结构比较、TeX/数字/公式/引用保护、MCM 结构与数学语义门、结果同步、复现、内容密度、XeLaTeX 编译和逐页检查。正式长文还把同一份逐节 packet 分别用于源稿和候选的判断桥审计：只有源稿中已存在的模型空降、局部依据或数学变化缺失、无记录比较等问题在候选中被修复，才计作内容收益；候选未通过同一契约时阻断。文风比较只负责相对收益和退化，不能证明作者身份。

## 采用标准

以下条件全部满足时，才把候选标为“建议采用”：

- 公式、数字、单位、标签、引用、图表路径、目标方向和关键限定没有未决漂移；
- 至少一类真实问题得到改善，例如直接跳模型得到补足、正文卡片链被改成连续论述、重复段首消失、结果解释落到具体对象；
- 没有新增列表支配、统一收束、同长短段串或大面积空泛扩写；
- 编译和项目硬门通过；
- 新生成的代码、图表和结果能由记录的命令重新得到，或明确标成未复现；
- 相对收益能用具体段落说明，而不是“更像人”“检测率更低”或命中数下降。

若只通过机械门而没有可信成对复核，交付状态写“候选已生成，建议人工快速比较”；不得声称“已经完全去除 AI 痕迹”。若候选没有清楚收益，保留源稿并报告未采用原因，这也属于正常完成。

## 默认报告

面向比赛队员只报告：候选路径、PDF 路径、主要改善的 3--8 个位置、被回退的高风险改动、尚缺的事实材料和编译状态。内部台账、角色回执和哈希保存在运行目录，不把它们堆进正文。
